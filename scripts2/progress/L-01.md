# L-01 — Lab shell, verdict and motion tokens

**Issue:** #41  **Commit:** see `git log --grep "L-01:"` on `labs`  **Status:** shipped

## What shipped
Every lab now renders in one shell, `src/labs/LabShell.tsx`. The shell holds the lab's mock and controls, then one verdict line ("1.4.3 fails", with a glyph), a Reset button, and one polite region set 500 ms after the reader's last change. The colour check (1.4.1, 1.4.3, 1.4.11, the Colour check page, Home hero) and fade-the-text (1.4.3, Home) use it. Motion tokens `--speed-state` and `--ease-out` landed, a verdict flip replays a short `lab-settle` scale, and `data-motion="off"` now has the same effect as reduced motion. The data-integrity test checks lab coverage against a shrinking to-come list and asserts the flagship set.

## Decisions made
- **Shell API:** `<LabShell as? className verdict said onReset>{mock, controls, readouts}</LabShell>`. Any other props (id, aria-*) go on the root element. `as="form"` is only for the colour check. The shell owns the live region and the 500 ms timer. A lab must not render a polite region of its own.
- **`said`:** a new `{ text }` object for each change the reader makes; `null`, or an unchanged object, for anything else. Reset passes `null`, so it is never announced, and it also cancels an announcement still waiting. The live region keeps its last text after Reset, which is not re-announced.
- **Verdict:** `{ criterion, passes }`, rendered by `verdictText`. The first render never animates. Each flip remounts the inner span with `.settle` (keyed on a flip count, using React's set-state-during-render pattern, so it is hydration-safe).
- **Colour check verdict depends on the page:** `pairVerdict(pair, criterion)`. On 1.4.11 it is judged at 3:1. Everywhere else, including 1.4.1 (which has no ratio of its own), it is judged as 1.4.3 at 4.5:1. The registry `Lab` now receives `{ criterion }` (the page's number). `ColourCheck` takes `criterion?`, defaulting to 1.4.3.
- **Fade verdict:** 1.4.3, judged on body text (`fadeState().verdict`).
- **Reset:** the colour check returns to the pair `useColourPair` started with (`PairModel.start`), not to a `?fg=/?bg=` preload, and clears the greyscale preview. Fade returns to 18%.
- **Flagship flag:** `flagshipFor?: '<num>'` on a `LabEntry` (a string, not a boolean, because the colour check is shown on three criteria). `colour-check` is the 1.4.3 flagship (several thresholds, presets, URL state). `flagshipCriteria()` lists the built ones.
- **Coverage:** `uncoveredCriteria(records, toCome)` in the registry. The skip list is `tests/labsToCome.ts`: one criterion per line, with blank lines between, so parallel tickets each delete their own line without conflicts. A test fails if a listed criterion already has a lab, so the list must shrink.
- **`data-lab-mock`** marks a lab's mock. `e2e/labs.spec.ts` excludes it from the axe check in the failing state only, because there it depicts the reader's own failure on purpose.
- The existing `verdict(ratio)` sentence function in ColourCheck was renamed `announcement(ratio)`. "Verdict" now means only the CONTEXT.md term. `ANNOUNCE_DELAY_MS` now lives in LabShell.
- The `.wide` preview spans 9 grid rows, to cover the new foot row.

## Deliberately left
- The fade scale fill's `width` transition and the preview's `filter` transition break "only opacity, transform, colour". The design guide §7 names both as older exceptions. They can be converted later; that is not in this slice.
- No UI toggles `data-motion` (the tweak bar is out of scope). The CSS hook exists and e2e sets the attribute directly.
- Flagship URL state for new flagships belongs to each flagship ticket.
