## Decisions made

**Each card names who actually pays.** These criteria read as politeness rules until you say
that an unexpected context change costs a sighted mouse user a moment and costs a magnifier or
screen reader user their whole orientation. 3.2.1's example makes the sharpest version of the
point: a keyboard user cannot get *past* a control that navigates on focus, because every
attempt to move on triggers it again.

**3.2.2's pass example states what does *not* count as a change of context.** Updating part of
the page in place is fine; the criterion is over-applied into "never react to input", which is
not what it says.

**3.2.3 and 3.2.4 are given different failure shapes** so they do not read as the same rule
twice: 3.2.3 is about the *order* of a shared menu, 3.2.4 about the *name* of a shared action.
Each says what it permits — you may add and remove nav items, and consistency is about sequence
rather than identical content.

**3.2.6 notes it does not mandate help on every page**, only consistency where help exists.
