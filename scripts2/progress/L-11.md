# L-11 — Language and status messages: 3.1.1, 3.1.2 and 4.1.3

**Issue:** #51  **Commit:** see `git log --grep "L-11:"` on `labs`  **Status:** shipped

## What shipped
3.1.1, 3.1.2 and 4.1.3 have live examples on both stages and a lab each. On 3.1.x, "Read it aloud" fills a voice log that names the voice for each line: an English mock page with no `lang` is read in the reader's default German voice, and a French phrase marked `lang="fr"` switches voice and back. On 4.1.3, Add to basket updates the count. The broken basket's log hears nothing. The fixed basket's log hears "Added. 4 items in basket." while focus stays on the button. The labs: "declare the page’s language" (radios: none / en / fr), "mark the French phrase" (a checkbox) and "announce the basket" (a status-region checkbox plus "Press Add to basket"). The real page's `lang` is never changed, and the 4.1.3 demo is untouched.

## Decisions made
- **`announce` breaks a text run where the language changes** (`src/labs/announce.ts`), so "read <em lang=fr>…</em>, which…" gives three lines. Punctuation after the phrase starts its own line (", which nobody obeyed."), as a voice switch does.
- **`liveRegionLines(root)`** in `announce.ts`: one line per live region (role status/alert/log, or aria-live polite/assertive) with its current text. It is used by both the stage and the 4.1.3 lab.
- **`StageEvent` `status`** (`src/live/events.ts`, included by `logOf`). `LiveStage` runs a MutationObserver over the example on both stages and pushes `status` when a live region's text changes. It reads attributes, so the inert fail stage is judged the same way.
- **LiveStage simulated activation** pushes `change` only when the activated control's spoken line changed. Before this, a plain button wrote its own name to the log again on every Enter.
- **Instrument `voice-log`** (`src/live/instruments.tsx`): the announcement log with `withVoices`. Voice labels are in `src/labs/language.ts` (`voiceOf`, `READER_DEFAULT = 'de'`). It puts the voice label in `Announcement.lang` for display only.
- `Choice` is now exported from `NameRoleValueLab.tsx`, the same edit L-09 makes.
- All three labs start failing. Their `e2e/labs.spec.ts` cases set `startsFailing`.
- The status region in the live and lab mocks is in the DOM from the start and is never `display: none`.

## Deliberately left
- The 3.1.x live examples have only "Read it aloud". There is nothing focusable to operate in a paragraph.
- Lab state is not kept in the URL. The issue doesn't ask for it.
