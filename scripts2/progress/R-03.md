# R-03 — All 55 criterion pages

**Issue:** #30  **Commit:** see `git log --grep "^R-03"`  **Status:** shipped

## What shipped
Every criterion in the manifest is pre-rendered at `criteria/<num>/` with the PRD's full anatomy, in
order: breadcrumb, head (meta line with marker, number, principle, level and New tag; h1;
restatement) beside the facts card, Broken then fixed, What changed in the code (diff), Watch it
happen (demo players), Try it yourself (labs), Also in guideline X.Y (index cards), and the pager.
The diff, demo and lab sections render only when the record has one. Old `/#1.4.3` links on the
home page are replaced by the criterion page with no history entry.

## Decisions made
- **Page helpers live in `src/site/criterionNav.ts`**, not `corpus.ts`: `neighbours(num)` →
  `{prev?, next?}` over `CORPUS` (number order) and `related(record)` → `{heading, byGuideline,
  records}` (same guideline, else same principle, at most six). Guidelines 1.1 and 2.3 fall back
  to "More from Perceivable / Operable".
- **Shared components:** `IndexCard` (render inside `ul.grid`; whole card is one link; principle
  name in an `.sr` span), `Tags.tsx` (`Marker`, `LevelTag`, `NewTag` — reuse these instead of
  writing `.mk`/`.lv` markup by hand), `Breadcrumb({trail, current})`, `Facts`, `Pager`.
- **Breadcrumb class is `.trail`, not the prototype's `.crumbs`**: the 2.4.x corpus examples
  already use `.crumbs` in `examples.css`, and the two collided.
- **`.surf` border is a token, `surf-edge`** (dark = card fill, light = `line`), per the R-01
  rule that light/dark CSS differences are tokens, not `[data-theme=light]` selectors.
- **Labs:** one "Try it yourself" section (h2); each lab is a `.lab-slot` with its registry
  `title` as an h3, then `<Lab />`.
- **Pager** is `nav[aria-label="Previous and next criteria"]` with `rel="prev"/"next"` links;
  at the ends only one link shows (an empty span keeps Next in the right column).
- **`useTimeline` is hydration-safe:** starts paused on server and client, starts playing in a
  mount effect unless reduced motion is set; `reducedMotion` comes from `useSyncExternalStore`
  (server snapshot `false`) and follows live changes.
- **Legacy redirect:** `src/site/legacyRedirect.ts` builds an inline script (only the 55
  manifest numbers; other fragments untouched) that `vite.config.ts` injects at
  `<!--@legacy-redirect-->` in `index.html`'s head. R-08 must keep the placeholder in Home's head.
- **Tests changed deliberately:** `e2e/demo.spec.ts` now runs on the criterion pages (one test
  per demo page, 9 players across 8 pages); the demo-library test stays on `/` until R-10.
  `e2e/navigation.spec.ts` "a deep-linked card is not obscured" was retired: `/#1.4.1` now
  redirects (that behaviour is covered in `e2e/criterion.spec.ts`).
- **Two corpus/example fixes the new pages exposed:** the 1.3.1 pass example's heading was an
  h5 (sized for the old card's h4); under the page's h2 it skipped levels, so it is now an h3.
  The 1.4.13 tooltips were hidden with `visibility`, so they still took room and widened the
  page at 320px; they now use `display: none` and cap at 60vw (`examples.css`).
- Seams tested: `routes.ts` (55 routes), `criterionNav.ts`, the server render of every page
  (`tests/criterionPage.test.tsx`: content without JS, section order and presence per record,
  lab section via a mocked registry, cards, pager), and the built site in the browser
  (`e2e/criterion.spec.ts`: all 55 built, no-JS, hydration errors, navigation, redirect, layout at
  1440/390). Seams were not confirmed with a human (run unattended).
