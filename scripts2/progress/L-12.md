# L-12 — Form errors and labels: 3.3.1 and 3.3.2

**Issue:** #52  **Commit:** see `git log --grep "L-12:"` on `labs`  **Status:** shipped

## What shipped
3.3.1 and 3.3.2 have live examples on both stages and a lab each, all with the announcement log. On 3.3.1 the Broken form shows a red border and an "Invalid input" banner. Tabbing through it, the field sounds the same as a field that was never wrong. The Fixed form has a summary that links to the field, plus `aria-invalid` and `aria-describedby`; submitting while the email is still wrong sends focus back to the field. On 3.3.2 the Broken fields are labelled by placeholders only, and the Fixed fields keep their labels, with the format tied to each field. In the 3.3.1 lab ("Try it: show the error") the reader picks a red border or text tied to the field, then submits. In the 3.3.2 lab ("Try it: label the field") the reader switches between a placeholder only and a label plus format, and types into the field. The typed text shows up in the mock, so the placeholder visibly disappears.

## Decisions made
- **`announce` names a text field from its placeholder** as a last resort, after title (HTML-AAM). This is in the header comment and covered by `tests/announce.test.ts`.
- Models: `src/labs/formErrors.ts` and `src/labs/formLabels.ts`. Verdicts are judged from the chosen design: border fails and text passes; placeholder fails and label passes. So the 3.3.1 verdict holds before the first submit, and both labs start failing.
- `Choice` is now exported from `NameRoleValueLab.tsx`, the same one-line change L-09 makes, so the merge is clean.
- Lab mocks reuse the live examples' `.lform` styles. The CSS is in swatch.css "Form errors and labels (L-12)", and `.flab__controls` stacks in the 900px block.
- Both live examples start in the state their caption describes: the 3.3.1 forms have already been submitted and rejected.
- 1.3.5: the real fields carry `autocomplete` (email, postal-code, bday, new-password).

## Deliberately left
