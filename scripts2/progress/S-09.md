# S-09 — Blog feed and Further reading on criterion pages

**Issue:** #77  **Commit:** (this commit)  **Status:** shipped

## What shipped
The prerender step writes an Atom 1.0 feed to `dist/blog/feed.xml` with every post in full,
newest first, every address absolute, and fails the build if the feed check finds a problem.
The blog index and every post page link the feed from their head. Each criterion page lists up
to three posts whose `criteria` include it, newest first, under "Further reading", between the
labs and "Also in", and has no such section when no post discusses it.

## Decisions made
- **Feed module.** `src/blog/feed.tsx`: `feedXml(posts, fallback)`, `feedProblems(xml)`,
  `feedLink(route)`. Build-time only (imports `react-dom/server`); `entry-server.tsx` exports
  `blogFeed(fallback)` (`POSTS` mapped through `postFor`), `feedProblems` and `FEED_PATH`
  (`blog/feed.xml`, in `routes.ts`). The feed is a file, not a route: not in `ROUTES` or the
  sitemap.
- **Feed shape.** Feed `id` = `https://…/blog/`, title "WCAG Encyclopedia blog", `self` and
  `alternate` links, `author` = the organisation (no byline, as in JSON-LD). Entry `id` and
  `alternate` link = the post's absolute URL (slugs are permanent, so the id is stable);
  `published` / `updated` = frontmatter dates as midnight UTC; `summary` = description;
  `content type="html"` = the body drawn by `PostBody`. Feed `updated` = the latest entry
  `updated`, or with no posts the blog index's last-commit date (prerender passes
  `lastmods.get('blog/')`).
- **Absolute links in content.** `PostBody` takes an optional `link` (default: the page's relative
  `href`). The feed passes `absoluteUrl`, so `/criteria/1.4.3/` in a post becomes
  `https://wcagencyclopedia.com/criteria/1.4.3/` in the feed. S-08's directive branches in
  `PostBody` must route any site link they draw through the same `href` so the feed stays
  absolute; an embedded lab will render its static markup into the feed (no script), so check it
  reads sensibly there, or skip directive nodes in the feed.
- **Feed validity** is checked by hand (no XML library in the build), like `sitemapProblems`:
  well formed (tag balance, no bare `&` or `<`), Atom namespace root, one feed `id`/`title`/
  `updated`, an author, the `self` link; per entry one `id`/`title`/`updated`/`content` and one
  `alternate` link, both absolute on `SITE_ORIGIN`; RFC 3339 dates; no duplicate entry id.
  e2e also parses the served feed with the browser's `DOMParser` (no `parsererror`, Atom root).
- **Head link is relative**, not absolute: `./feed.xml` on `/blog/`, `../feed.xml` on a post.
  ADR 0006's "blog feed" exception covers the feed's contents; the link between pages stays
  relative (ADR 0001). So `e2e/criterion-page.spec.ts`'s cross-origin `<link>` check needed no
  change. `rel(from, to)` appends `/` to every segment, so it can't build a file path: the link is
  `rel(route.path, 'blog/') + 'feed.xml'`.
- **Further reading.** `postsAbout(num, posts)` and `FURTHER_READING = 3` in `src/blog/post.ts`.
  `CriterionPage` takes `posts` (default `[]`); `Site` passes `POSTS` (frontmatter only, already
  in the client bundle, so hydration renders the same list). Section id `reading-title`; post
  titles are h3 links in `ul.posts.posts--reading` with date and description (`.posts h3` shares
  the `.posts h2` rule).
- **Section order** is now: Broken then fixed, diff, demos, labs, Further reading, Also in.
  **S-17** puts "How to test" and "Common questions" between the examples and the labs, so before
  Further reading. `tests/criterionPage.test.tsx`'s per-record h2 list runs with no posts, so it
  already asserts no "Further reading" heading on all 55 pages; `tests/furtherReading.test.tsx`
  covers the populated case with mocked `POSTS`.
- **CONTEXT.md**: "Blog feed" and "Further reading" added.
- **Test changed deliberately:** `tests/homePage.test.tsx` asserted every non-home page's
  `head` is `''`; the blog index's now holds the feed link, so for blog and post pages it now
  asserts no redirect script (the exact head is asserted in `tests/blogBuild.test.ts`), and stays
  `''` for every other page.

## Deliberately left
- Post-to-post links and `/blog/feed.xml` links inside post bodies: not accepted by `parse.ts`
  (S-07's rule); add when a post needs one.
- Writing test over posts: S-10. Directives: S-08 (see the note on `PostBody` above).
- The built site ships no post, so the feed has no entries in the committed build. I built once
  with the fixture post copied into `src/blog/posts/` and ran the blog, axe (post page, 1.4.3 and
  1.4.11 with Further reading, both themes and 320px), crawl, placeholders and the font/link
  spec: all green; the feed had one entry and 1.4.3/1.4.11 showed the section.
