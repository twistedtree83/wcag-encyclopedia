## What shipped
`procedure` and `questions` on all 20 Operable criteria (principle 2), in `src/criteria/g2-1.tsx`
to `g2-5.tsx`: 2.1.1, 2.1.2, 2.1.4, 2.2.1, 2.2.2, 2.3.1, 2.4.1 to 2.4.7, 2.4.11, 2.5.1 to 2.5.4,
2.5.7 and 2.5.8. Each has 4 to 6 steps and 3 questions. Content only: no code, CSS or test
changes.

## Decisions made
- No new test. The ticket asks for no check beyond `npm run verify`; the existing writing test
  already runs over every record's steps and answers, and S-21 makes the fields required.
- Each answer was checked against the W3C WCAG 2.2 Understanding document for its criterion
  (fetched on 2026-11-28) and restated, not quoted.
- Answers that rest partly on inference, not on a line of the Understanding document:
  - 2.1.1, hover-only menu: inferred from failure F54 (pointer-only event handlers); the
    document names no hover menus.
  - 2.2.2, pause on focus: the document says a focus-based stop does not count; the "starts
    again" reason is ours.
  - 2.5.4, tilt-controlled game: the document's essential example is a pedometer; the game
    case applies the same exception.
  - 2.4.2, unique titles: the document does not require them; the answer says so.
  - 2.4.1, skip link hidden until focus: the document is silent; the answer rests on 2.4.7.
- Tools named: browser accessibility inspectors (Chrome/Edge DevTools, Firefox), NVDA,
  VoiceOver, Voice Control (Mac), Voice access (Windows 11), PEAT for 2.3.1.
- "unlock" is banned anywhere (a gesture "traced to unlock" failed): write around it.
- `tests/styleRules.test.ts` also reads every criterion record and bans the word "rule" or
  "rules" there, even for CSS (":focus rules" failed). The writing test does not catch it; only
  the full unit run does. Say "styles" or "selectors".
