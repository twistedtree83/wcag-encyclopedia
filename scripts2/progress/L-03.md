# L-03 — Live examples and simulated input, piloted on 4.1.2

**Issue:** #43  **Commit:** see `git log --grep "L-03:"` on `labs`  **Status:** shipped

## What shipped
A criterion's Broken and Fixed stages can now become live examples. The page pre-renders the static examples as before, then swaps in the live ones after hydration. Each live stage has the example, an input bar ("Press Tab", "Shift+Tab", "Space", "Read it aloud") and its instruments beneath it. On the Broken stage the example is inert and `aria-hidden`; the bar drives a focus model and draws a ring. On the Fixed stage the example is real, and both real keys and the bar move real focus. 4.1.2 is the pilot: the broken toggle says "blank" when focused, the fixed switch says "Email notifications, switch, on/off".

## Decisions made
- **Record shape:** `Example.live?: { Example: ComponentType; keys: SimKey[]; instruments: string[] }` in `src/criteria/types.ts`. Give it on both `fail` and `pass` with the same `keys`, or on neither. The data-integrity test checks this, and checks that instruments resolve.
- **Swap after hydration:** `Examples` in `CriterionPage.tsx` sets `hydrated` in an effect. Only then does it render `LiveStage` and add `.ex--live`. Records without `live` render exactly as before.
- **Events seam:** `src/live/events.ts` `StageEvent` (`focus` with index/total, `change`, `read`). Each carries `Announcement` snapshots and `simulated`. Instruments (`src/live/instruments.tsx`, registry `INSTRUMENTS`) are pure views of the events, so one instrument serves both stages.
- **Focus model:** `src/live/focus.ts`. `isTabbable(tag, attrs)` judges from attributes, because an inert example can't be focused. `step` wraps at both ends. `tabStops(root)` and `pathTo`/`nodeAt` map a DOM element to its `AxNode` copy.
- **Fail-stage markup keeps its real `tabindex`** (no `tabIndex={-1}`): `inert` stops real focus, and axe 4.13 passed with it.
- **`focusLine(node, within)`** in `announce.ts`: what is said when focus lands on the node. A roleless node is said by its text, so an empty one is "" and the log shows "blank" (`.alog__blank`).
- **Fixed an announce bug:** `<input type="checkbox" role="switch">` now reads its native checked state. Before, it was read from `aria-checked`, which this input doesn't have, so the state was missing.
- **Activation:** Enter activates buttons and links; Space activates buttons, checkboxes and radios, through `el.click()`. A div does nothing, which is realistic.
- **Live region:** each live stage has one `p.sr[aria-live=polite]`. It speaks simulated events and read-alouds only. Real focus is already spoken by the reader's own AT.
- **Layout:** above 900px, `.ex--live` lines the stages up on a CSS subgrid of four rows (caption, example, bar, instruments), so the logs match row by row. At 900px and below they stack in one column.
- **The ring** moves by `transform` and fades in by `outline-color`. The token test bans `opacity` on text. Reduced motion is handled globally.
- The 4.1.2 diff's "before" line gains `tabindex="0"`, to match the live broken toggle.
- How-to for later tickets: CONVENTIONS "Labs" points to `e2e/live-examples.spec.ts` and this ledger.

## Deliberately left
- Escape and Hover keys, the pointer and cursor drawing, and focus-tracker rects belong to L-04 and later tickets. Each adds a `SimKey` member, a `StageEvent` field and an instrument.
- Live examples for other criteria belong to their own lab tickets.
