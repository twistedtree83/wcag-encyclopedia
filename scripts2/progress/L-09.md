# L-09 — Sequence, input purpose and label in name: 1.3.2, 1.3.5 and 2.5.3

**Issue:** #49  **Commit:** see `git log --grep "L-09:"` on `labs`  **Status:** shipped

## What shipped
1.3.2, 1.3.5 and 2.5.3 now have live examples on both stages and one lab each. 1.3.2: checkout steps as buttons. On the Broken stage CSS `order` sorts them on screen, but simulated Tab and the read-aloud follow the source, Confirm first. The lab "Try it: reorder the steps" lets the reader set the source order and the CSS, and the log reads in source order. 1.3.5: the contact fields with and without `autocomplete`. A new "Autofill" key fills only fields whose token names a purpose. The lab "Try it: tag the fields" offers none, the right token or an invented token per field, and the mock fills as a simulated browser would. 2.5.3: a Send button whose aria-label replaces or extends its text. A new "Say what you see" key says "click" plus the visible text and clicks the control whose name matches. The lab "Try it: say what you see" edits the visible text and the aria-label separately.

## Decisions made
- **New keys:** `SimKey` gains `autofill` ("Autofill") and `voice` ("Say what you see"). Their branches in `LiveStage.press` are self-contained. `voice` takes the phrase from the first Tab stop's visible text (`textContent`), not its name.
- **New events and instruments:** `StageEvent` gains `autofill` (`fields: {name, value}[]`) and `voice` (`phrase`, `clicked: Announcement | null`). Instruments `autofill` and `voice-control` show the latest one (`lastOf(events, kind)`). Their spoken sentences are `autofillSaid` / `voiceSaid` in `events.ts`. Both stages speak these, because the outcome comes from the bar, not from the reader's own AT.
- **announce:** a text field's live value is now said after its other states ("Email, edit text, required, ada@example.com"). `AxNode` gains `value`, and `fromDom` reads `.value` from inputs and textareas.
- **Pure models:** `src/labs/sequence.ts` (verdict: the source is 1, 2, 3; CSS can't fix it), `src/labs/inputPurpose.ts` (`purposeOf`: the last token must be one of the HTML autofill field names behind WCAG's input-purpose list; `autofillValue` is the simulated browser's saved profile), and `src/labs/labelInName.ts` (`voiceMatches`: whole words, in order, ignoring case and punctuation).
- `Choice` (radio fieldset) is now exported from `NameRoleValueLab.tsx` and reused by two of these labs.
- All three labs start failing (`startsFailing` in `e2e/labs.spec.ts`). There is no URL state: they aren't flagships.
- Shared lab layout classes are `.lab-controls` (an auto-fit grid of choices), `.lab-out` and `.lab-code`, in the swatch.css "L-09" section. Later labs can reuse them.
- The 2.5.3 live button does nothing visible when clicked. A counter would have been an unannounced status message (4.1.3), so the voice-control instrument reports the click instead.

## Deliberately left
- Real voice-control input (speech) is out of scope. The bar simulates it on both stages.
- The labs' axe check runs in the default viewport and theme (labs.spec), as for the earlier labs. The live examples are scanned in all four modes after they are operated.
