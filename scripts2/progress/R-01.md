# R-01 — Walking skeleton: pre-rendered 1.4.3 page and the Swatch shell

**Issue:** #28  **Commit:** see `git log --grep "^R-01"`  **Status:** shipped

## What shipped
The build now pre-renders pages to static HTML and hydrates them (ADR 0001), proven on
`/criteria/1.4.3/`: its head (meta line, h1, restatement) and Broken / Fixed stages are in the
markup before any script runs. Every pre-rendered page gets the Swatch shell: skip link, header
(logo, Main nav, theme toggle), footer. The Swatch tokens replace the old palette in both themes,
and only Figtree and Onest load. The old single page keeps running at `/`.

## Decisions made
- **Pipeline:** `npm run build` = client build (`index.html` + `site.html` inputs, `appType: 'mpa'`
  so missing pages 404) → SSR build of `src/entry-server.tsx` into `dist-ssr/` → `scripts/prerender.mjs`
  fills `site.html` per route and writes `dist/<path>index.html`. The client reads its route from
  `#root[data-route]`, never from `location.pathname` (Pages prefix). `<Site>` sets
  `<html data-hydrated="true">` once hydrated; e2e waits on that.
- **Routes:** `src/site/routes.ts` is pure data (e2e imports it). Paths have no leading slash and a
  trailing slash. `FIXED_ROUTES` for non-criterion pages, `PUBLISHED_CRITERIA` for criterion pages
  (only 1.4.3 now). All links are relative via `useRoute().href()` / `rel()`. The axe spec loops
  `ROUTES`, so a new page is scanned as soon as it is routed.
- **Tokens:** Swatch names verbatim; design aliases resolved to hex per theme in `withAliases()`.
  The audit checks every row of the guide's §3.4 table at its threshold (and that the palette
  still produces the guide's ratios ±0.06); failure messages name theme, pair, ratio and threshold.
  Tightest pair `line-2` on `card-bg` in dark is pinned at 3.7:1.
- **Old palette deleted, old page kept alive** by renaming every old token reference (ink2/ink3→ink-2,
  panel→card-bg, panel2 and the washes→deep, rule→line, rule2→line-2, link/p1..p4 text→accent-text,
  fail→err-text, pass→ok-text). Example colours renamed `swatch-*` → `ex-*` and audited on `--deep`,
  the stage surface. `PRINCIPLE_MARKS` tokens are now `a1..a4` (fills only).
- **Light/dark differences in CSS are tokens** (e.g. `stage-edge-bad/good`), never
  `:root[data-theme=light]` selectors, because a no-JS reader on a light OS has no attribute.
- **Theme-dependent content is rendered once per theme** with `data-theme-only`; `tokensCss()` hides
  the inactive copy. `MeasuredRatio` works this way, so it is correct without JS and hydrates cleanly.
- **`useTheme` is SSR-safe:** `useSyncExternalStore` over `<html data-theme>` (server snapshot
  `light`), so `aria-pressed` is corrected straight after hydration instead of left mismatched.
- **Theme toggle:** one button "Dark theme" with `aria-pressed`, `btn o sm`, ≥44px, drawn ink-filled
  when pressed. The old page uses the same component (old "Dark mode/Light mode" label retired).
- **CSS:** `src/styles/swatch.css` (shell, non-colour tokens; add new components as sections before
  "Breakpoints"), `src/styles/examples.css` (example and demo styles, split out of `global.css` and
  shared by both pages), `global.css` (old page only). Old page fonts switched to Figtree/Onest, mono to
  the system monospace.
- **Header on phones:** links wrap under the logo; the toggle sits on the logo's row, right-aligned
  (it wraps to its own row below about 400px).
- Seams tested: token module (audit), `routes.ts` (`rel`, route list), built HTML with JS disabled,
  and the hydrated page in the browser (shell, toggle, fonts, axe).
