# L-02 — Announcement log and the 4.1.2 flagship lab

**Issue:** #42  **Commit:** see `git log --grep "L-02:"` on `labs`  **Status:** shipped

## What shipped
The announcement log instrument: `src/labs/announce.ts` computes, from a markup subtree, what a screen reader would say line by line (name, role, states, description, language), and `src/labs/AnnouncementLog.tsx` reads the rendered DOM after each commit and draws the lines. Its first use is the 4.1.2 flagship lab, "Try it: build the toggle". The reader picks the element (div, `<button>`, `role="button"`, `role="switch"`), the name source and the state attribute, and can switch the toggle on or off. The log, the markup readout and the verdict follow. The lab's state lives in the URL.

## Decisions made
- **Seam:** `announce(node: AxNode)` takes a plain copy of the markup (`AxNode`: tag, attrs, live `checked`, children), not a DOM element. In the browser `fromDom(el)` makes one. Vitest runs in Node with no DOM, and adding jsdom was refused, so `tests/markup.ts` parses React's `renderToStaticMarkup` output into an `AxNode`. That parser is test-only and handles only well-formed React output.
- **Subset:** documented at the top of `announce.ts`. Names: labelledby > aria-label > label/alt/value > content (for roles named from content) > title. A state the role doesn't support is ignored, so `aria-checked` on a button says nothing. A button with `aria-pressed` is a "toggle button". `textbox` is said as "edit text". Text runs are merged until a block element or a role line. The root is read even when it is `aria-hidden`, because mocks are hidden on purpose.
- **Spoken form:** `spoken()` gives "name, role, states…, description", plus " (lang)" when a `lang` applies.
- **The mock is depicted, not live:** `aria-hidden="true" inert`, and the native button gets `tabIndex={-1}`. axe passes on broken URL states because the mock is hidden.
- **Verdict from the model, checked against the log:** `nrvVerdict` is computed from the model, so the page can pre-render it. A unit test renders every combination (4×4×3×2) and asserts that it matches `exposure(log)`.
- **`said`:** `{ text: saidFor(lines) }` whenever the reader's change counter `heard` is above 0. A preload and Reset leave it at 0. Example text: "Screen reader says: …; …. Missing name." or "Role, name and state all exposed."
- **The lab starts failing** (a bare div). `e2e/labs.spec.ts` `LabCase` now accepts `startsFailing: true` with `toPass`, in place of `toFail`. Existing entries are unchanged. That test now runs axe in both states, start and driven.
- **URL:** `?el=&name=&state=&on=1|0` in `src/labs/nrvQuery.ts`. The start writes no query, and unknown values fall back to the start. The query is applied in a mount effect. Write-back uses `replaceState` and skips the first effect run. Reset clears the query.
- Controls are radio groups rather than selects, so arrow keys drive them reliably by keyboard in e2e.

## Deliberately left
- The log is empty in the pre-rendered HTML and fills on hydration. It is computed from the DOM, and there is no DOM on the server.
- Simulated input ("Read it aloud") and the live-example stage layer belong to the live-example ticket. The log already accepts any element, real or inert.
- Language of parts is in the computation and tested, but the 4.1.2 lab doesn't use it.
- The 4.1.2 record's static Broken and Fixed examples still use hand-typed `a11ytree` text. Moving them onto the log belongs to the live-example work.
