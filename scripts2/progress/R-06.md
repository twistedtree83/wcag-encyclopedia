# R-06 — Colour check

**Issue:** #33  **Commit:** see `git log --grep "^R-06"`  **Status:** shipped

## What shipped
The colour check is a lab built once in `src/labs/ColourCheck.tsx`. It is mounted wide on the new
`/colour-check/` page, with quick-start chips, "Done well, done badly", "What the numbers mean"
and "What a ratio can't tell you". It also appears under "Try it yourself" on 1.4.1, 1.4.3 and
1.4.11. Every ratio comes from the contrast engine and the colours actually drawn: the score,
the four results, the fix suggestion, the pair badges and the live verdict.

## Decisions made
- **Engine additions (`src/color/contrast.ts`):** `AAA_BODY = 7`, `normaliseHex(s)` (3 or 6 digits,
  `#` optional, returns `#RRGGBB` or `null`, never throws), `formatScore(r)` ("4.49", two
  decimals, truncated), `passesThreshold(r, t)` (judged on that truncation; `meetsAA` now calls
  it), and `nearestPass(fg, bg, target = 4.5)` (mixes towards black and white in 1% steps, keeps
  the smaller change). `formatRatio` (one decimal) is unchanged. R-07: reuse these.
- **State is owned by whoever mounts the check:** `useColourPair(initial?)` returns
  `{ fg, bg, changes, set(fg, bg, { announce? }) }`; `<ColourCheck state id? wide? title?>`
  renders it. That is how the page's chips, pair cards and `?fg=`/`?bg=` load pairs, and how
  R-08's Home hero should mount it (`useColourPair()` + `<ColourCheck state={…} title="Check a
  colour pair" />`). `ColourCheckLab` is the registry entry (no title; the form is named "Colour
  check"; it ends with an "Open the full colour check" link that carries the current pair as
  `?fg=RRGGBB&bg=RRGGBB`).
- **Ids:** pass `id` for a fixed prefix (the page uses `cc`, so the text-colour field is `#cc-fg`);
  without it the check uses a `useId()` prefix, so two checks on one page never collide.
- **Live verdict:** announced 500ms (`ANNOUNCE_DELAY_MS`) after the reader's last change, never
  on first render or on the URL preload (`announce: false`). Copy from `verdict(ratio)`.
- **`?fg=`/`?bg=` are read in an effect after hydration**, so the static HTML always shows the
  default pair (ink on sun) and hydration matches.
- **Results copy:** "Body text, AA · 1.4.3" … "Borders and icons, AA · 1.4.11", each with
  "Threshold N : 1" (the ticket asks for "thresholds" in on-screen copy). The AAA row is a
  result only; nothing on the page links to 1.4.6.
- **Pair cards** (`src/components/PairCard.tsx`, render inside `ul.pairs`): the badly tile's
  sample is `span.sm[data-t][aria-hidden]` drawn by `::before`; the badge says "Badly · N : 1"
  plus an `.sr` "#FG text on #BG.". Not marked `data-depicts-failure` (nothing in it fails axe).
  Data in `src/labs/pairs.ts` (`DEFAULT_PAIR`, `PRESETS`, `PAIRS`).
- **New token `chk-edge`** (dark = deep, so no visible edge; light = line), instead of the
  prototype's `:root[data-theme=light] .chk` selector. Decorative, so not in TOKEN_PAIRS.
- `tests/criterionPage.test.tsx`'s registry mock now falls through to the real registry
  (`importActual`) so real records with labs still render beside the fixture lab. A fixture
  change, no assertion removed.
- Labs ids: `labs: ['colour-check']` on 1.4.1, 1.4.3 and 1.4.11. R-07 appends `'fade-text'` to
  1.4.3's list.
- Seams tested: the engine (`tests/contrast.test.ts`), the server render of the page and the
  three labs (`tests/colourCheck.test.tsx`), and the built page in the browser
  (`e2e/colour-check.spec.ts`). Seams were not confirmed with a human (run unattended).
