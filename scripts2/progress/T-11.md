# T-11 — Demos: focus and keyboard (2.4.7 ×2, 2.4.11)

**Issue:** #11  **Status:** shipped

## What shipped

Three timelines — `focus-visible-2-4-7`, `focus-lost-2-4-7`, `obscured-2-4-11` — authored
against the existing runtime. **The player was not modified**, which was the issue's own test of
whether T-09's abstraction held. It did.

## Decisions made

**The two 2.4.7 demos are generated from one function.** `traversal(ring: boolean)` produces
both keyframe lists, so they share a layout, a schedule, and a set of fields, and differ in
exactly one authored value. The reader is comparing one variable, not two scenes. The captions
differ because the *experience* differs — the failing one narrates what the reader cannot know
("Tab again. Typing now would go into a field the reader cannot identify") rather than restating
the visuals.

**The 2.4.11 demo changes `padded` mid-timeline**, so the fix is applied inside the demo rather
than shown as two separate demos. The reader watches the same traversal fail and then work.

### `demo` became `demos`

Registering both 2.4.7 timelines exposed a real gap: a criterion record could name only **one**
demo, so `focus-lost-2-4-7` was registered, listed in the library, linked to `#2.4.7` — and
rendered nowhere. Following that link led to a card that did not contain it.

`CriterionRecord.demo?: string` is now `demos?: readonly string[]`, and the card renders them in
order. **A new test closes the hole permanently**: every registered demo must be named by some
criterion card, so a demo can never again exist without a place to be seen.
