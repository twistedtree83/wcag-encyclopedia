# S-05 — A real 404 page

**Issue:** #73  **Commit:** see `git log --grep "^S-05:"`  **Status:** shipped

## What shipped
A pre-rendered "Page not found" page in the site shell (`src/pages/NotFoundPage.tsx`), with
buttons to all criteria, the home page and the blog (`/blog/`, built by S-07). The prerender
step writes it to `dist/404.html`, `noindex` and without a canonical tag, and Cloudflare serves
it with status 404 for any path that matches no asset (`not_found_handling: "404-page"` in
`wrangler.jsonc`).

## Decisions made
- **Not a route.** `NOT_FOUND = { path: '404.html', page: 'not-found' }` in `src/site/routes.ts`
  sits outside `ROUTES`, so the sitemap, the canonical check, S-02's head-metadata test and the
  per-route axe loops never see it. `routeFor('404.html')` returns it so the client hydrates.
  `PageKind` gained `'not-found'`: `SECTION` in Header maps it to `undefined` (no nav item
  current) and `PAGE_FILES` in crawl.ts names its file (only to satisfy the `Record`).
- **Served at any depth**, so it cannot link relatively. `linkFrom(route, to)` in routes.ts
  (used by `useRoute().href`) gives `/${to}` for the 404 page and `rel(...)` for every other
  page; the prerender step writes its assets as `/assets/…` and fails the build on a relative
  `href`/`src`, a canonical tag, or missing `noindex`. Root-absolute links assume the site is
  served from the domain root (Cloudflare), not a GitHub Pages sub-path.
- **`noindex` goes through `render()`'s `head`** (`NOINDEX` exported from entry-server), like
  Home's legacy redirect. S-03/S-04 adding head markup: keep both.
- **No Worker code.** The Worker already hands every non-www request to `env.ASSETS.fetch`,
  which applies `not_found_handling`. Not verified against a live deploy or `wrangler dev`
  (wrangler is not a dependency): check `curl -I https://wcagencyclopedia.com/nope/` returns
  404 with the page after the first deploy.
- **`vite preview` mirrors Cloudflare**: the `notFoundPage` plugin in `vite.config.ts` answers
  any request no built file matches with `dist/404.html` and status 404, so e2e tests the page
  as readers get it. A URL without its trailing slash also gets it in preview (Cloudflare
  redirects that instead), so e2e only uses trailing-slash unknown paths.
- `e2e/not-found.spec.ts` holds the 404 page's own checks (status at three depths, links,
  noindex and sitemap, axe in the four modes, focus outlines, hydration, 320px). It opens pages
  with its own `openMissing` (expects 404, then `whenReady`), since `open()` insists on 200.
