# S-04 — Structured data

**Issue:** #72  **Commit:** see `git log --grep "^S-04"`  **Status:** shipped

## What shipped
Every built page carries JSON-LD in its head: `WebSite` (with a `SearchAction` into All
criteria's `?q=`) and `Organization` on Home, a `BreadcrumbList` on every other page, and a
`TechArticle` on each criterion page with its headline, an `about` naming the criterion, git
dates, and the organisation as author and publisher. The prerender step fails the build on any
block that doesn't parse, a wrong set of block types, a missing required property, or an
address that isn't absolute on `SITE_ORIGIN` or isn't the page's own route.

## Decisions made
- `src/site/jsonLd.ts` (pure, e2e imports it) builds the blocks (`jsonLdBlocks`,
  `jsonLdScripts`) and checks them (`jsonLdProblems`). It is a sibling of `crawl.ts`, not part
  of it, to keep S-03/S-05's edits to `crawl.ts` apart from this one. Extension points:
  `BLOCKS` and `TYPES` (`Record<PageKind, …>`, so a new page kind fails to compile until it
  adds both) and `REQUIRED` / `CHECKS` keyed by block `@type`. S-07 adds `BlogPosting` there.
- `structuredData(route, { published, modified })` in `src/entry-server.tsx` gathers the facts.
  It is separate from `render(route)` because only the prerender step can read git dates, and
  `render`'s fields and head are where S-03/S-05 are working.
- `<!--@structured-data-->` in `site.html`, after the canonical tag. `dateModified` is the
  sitemap `lastmod` (computed once per page now, in the page loop); `datePublished` is the
  first commit to the same `pageSources` files, so a criterion page is dated from its guideline
  file (older than a criterion added to it later).
- The breadcrumb trail is one function, `trailFor(route, name)` in `src/site/breadcrumbs.ts`,
  used by both the visible `Breadcrumb` (which now takes `trail: Crumb[]`, the last crumb the
  page itself) and the `BreadcrumbList`. The page's own name is `pageName(route)` in
  `src/site/Site.tsx` ("Criteria", "Colour check", "About", "1.4.3 Contrast (Minimum)"). Only
  criterion pages show a trail; the fixed pages get a `BreadcrumbList` (Home, page) without a
  visible one, as the ticket asks for a breadcrumb on every page below home.
- Author and publisher are written in full (`Organization`, name, url) in each `TechArticle`
  rather than by `@id`, since the `Organization` block is only on Home.
- `about` is a `DefinedTerm` (name "1.4.3 Contrast (Minimum)", `termCode`, in the set "WCAG 2.2
  success criteria"). No `sameAs` to w3.org: the ticket keeps every URL on `SITE_ORIGIN`.
- No `logo` or `image` yet. S-03's share cards could supply `image` for `TechArticle`; the URL
  check already treats `image` and `logo` as addresses that must be on `SITE_ORIGIN`.
- The `SearchAction` is kept although Google retired the sitelinks search box; the ticket asks
  for it whenever the index accepts a query parameter, and it does.
- New CONTEXT.md terms: **Breadcrumb trail** (crumbs) and **Structured data**.

## Deliberately left
- `BlogPosting` on posts: S-07.
- An `image` on articles from the share cards: S-03 or later.
- The 404 page (S-05) needs no JSON-LD; if it gets a `PageKind`, `BLOCKS` and `TYPES` need an
  entry (an empty list works).
