# L-06 — Focus order and bypass: 2.4.1, 2.4.3 (flagship) and 2.4.11

**Issue:** #46  **Commit:** see `git log --grep "L-06:"` on `labs`  **Status:** shipped

## What shipped
Live examples on both stages, under the focus tracker, for 2.4.1 (a shop page with an eight-link menu; Fixed adds a skip link whose Enter puts focus on the article), 2.4.3 (a filters dialog; Broken leaves focus on the page behind it, Fixed moves focus in, makes the page inert, and returns focus to "Show filters" on close) and 2.4.11 (a short scrolling checkout with a sticky header; Broken lets a field scroll under the header on the way back up, Fixed has `scroll-padding-top`). Three labs: "Try it: count the Tab presses" (2.4.1, skip link on/off and menu length), the 2.4.3 flagship "Try it: break the focus order" (source order and positive tabindex on a grid-placed form, numbered focus order on the mock, state in the URL), and "Try it: move the sticky banner" (2.4.11, banner position and height, share of the focused field hidden).

## Decisions made
- **Positive tabindex is now real in the focus model:** `tabOrder` in `src/live/focus.ts` (pure, unit-tested) sorts stops the HTML way; `tabStops` uses it. The 2.4.3 lab's model calls the same function.
- **`tabStops` skips `inert` subtrees inside the root** (not the root itself, which is inert on the fail stage). Needed for the page behind 2.4.3's open dialog.
- **Fail-stage Tab scrolls scrolling boxes inside the example** (`revealWithin`, LiveStage), honouring `scroll-padding-top`, never the page. That is how 2.4.11's Broken field ends up under the header with simulated input only.
- Covering content (2.4.3 dialog, 2.4.11 header) sits at `z-index: 2`, above the drawn `.sim-ring`, so a ring under an overlay is hidden as real focus would be. The focus tracker still says where it is.
- 2.4.1's fail caption was "Forty links before the article"; the live page has eight, so it now reads "Every menu link stands between the reader and the article." (true of static and live).
- Links in the live examples have `href="#"` with the click prevented, so the fail stage's Enter (a programmatic click) never navigates.
- `Slider` is exported from `FocusRingLab.tsx` with optional `min`/`max`/`step`; the 2.4.1 and 2.4.11 labs reuse it.
- 2.4.3 URL: `?src=layout|columns|send-first&ti=none|postcode|send` (`src/labs/orderQuery.ts`); start writes no query.
- 2.4.11 lab verdict: fails only when the field is 100% hidden (Minimum); partly hidden passes and says so.
- **Test fixed deliberately:** `e2e/live-examples.spec.ts` "criteria without live examples keep their static stages" used 2.4.11 as its example of a non-live criterion; 2.4.11 is now live, so it uses 1.2.1.
- Seams tested: `tabOrder`, the three lab models and the 2.4.3 query (vitest); everything else on the built page (e2e).

## Deliberately left
- The 2.4.11 demo and all static examples/diffs are untouched.
- No "focus left the example" event (2.1.2, L-05/L-07). When 2.4.3's Broken dialog closes with simulated focus on Close, the ring simply disappears until the next Tab.
- The drawn ring is placed on simulated focus moves and resize only; it does not follow a layout change from Enter (the dialog opening).
