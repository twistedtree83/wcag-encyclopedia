## Decisions made

**The example attacks the failure mode that automated checkers miss.** All three failing images
*have* alt attributes, so axe reports no error — they are described as "image", by filename, and
a decorative divider is announced to everyone. The pass side shows the same three images
described by *purpose*, including `alt=""` for the decorative one. The point being taught is
that "is there alt text" is the wrong question.

**Three images rather than one**, because the common mistake is applying a single rule to
informative, complex, and decorative images alike.

### Two test-hygiene fixes that matter to the remaining twelve content tasks

**1. e2e counts are now derived from the corpus, not hardcoded.** `filter.spec.ts` asserted
"3 criteria documented" and "1.4.3 is not yet authored". Every content task would have broken
it for no reason. It now imports `CORPUS` and computes totals, picks an undocumented guideline
dynamically, and skips the not-yet-documented test once the corpus is complete. **Do not
hardcode a corpus count in a test.**

**2. Locators that assume one match will break as content lands.** The diff test used
`.diff__line--del` expecting a single line; 1.1.1's diff has two. It now checks the first and
separately asserts every removed line carries its screen-reader prefix — which is the stronger
assertion anyway.
