# T-09 — Demo timeline runtime, player, and the reflow demo (1.4.10)

**Issue:** #9  **Status:** shipped

## What shipped

The mechanism all nine demos are built on, proven against 1.4.10 Reflow. A demo is a
declarative timeline; `frameAt(timeline, t)` is a pure function returning the state and caption
in effect; the player is a thin shell that changes `t`. Eight demos remain (T-11, T-12) and
they are now content authoring, not engineering.

## Decisions made

**`frameAt` is pure and total, and it is the only path to the screen.** No clock reads, no DOM,
no side effects. Everything playback needs is a change to `t`:

| control | implementation |
|---|---|
| pause | stop advancing `t` |
| scrub | set `t` |
| loop | `wrap(t, duration)` — modulo, not a restart branch |
| reduced motion | never advance `t`; scrubbing still works |

`useTimeline` owns `t` and nothing else. It renders nothing and never touches a frame. **If a
later demo appears to need the player changed, the abstraction is wrong — raise it rather than
special-casing.**

**Captions live on keyframes**, so a caption cannot desynchronise from its visual state. A test
asserts the returned caption and state come from the same keyframe object at every sampled
time, which is the property the whole design exists to guarantee.

**`frameAt` also returns `progress`, 0..1 through the current segment.** This is what lets a
demo interpolate smoothly while the caption steps — the reflow demo lerps its width and the
caption changes at breakpoints. It keeps `frameAt` a step function (simple, testable) without
forcing every demo to look like a slideshow.

**Captions must be true for the whole span they are shown.** The first draft read "At 620px the
grid drops to two columns" while the live ruler showed 583px a moment later — the caption steps,
the width does not. Captions now name the *breakpoints* (`Below 780px…`), which is both honest
throughout the segment and the more useful thing to teach. A test rejects any non-final caption
matching `At <n>px`, so this cannot creep back in.

**Demo state is authored as the input to the layout, not as the layout.** The reflow demo's
state is just `{ width }`; columns, nav collapse, and the ruler all derive from it — the same
way a real responsive layout derives from a real viewport. This keeps timelines short and makes
the demo honest: it cannot show three columns at 320px, because nothing draws columns directly.

**Scrubbing pauses.** Keeping the clock running while the reader drags would fight their input.

**The registry erases the timeline's state type at the boundary** — each entry exposes a
`Player` component that closes over its own timeline and renderer. `frameAt` stays generic and
type-safe inside a demo; the registry stays a flat list that the card and the demo library
(T-10) both read.

## Deliberately left

- Eight timelines — T-11 (focus and keyboard) and T-12 (announcements, errors, targets,
  motion). Both should add files under `src/demo/demos/` and one registry entry each.
- The demo library index — T-10. `DEMOS` is the list it should render.
- The stage is 16:9 with the mock centred; at very small container widths the mock gets small.
  T-06 owns container queries and may want to revisit the stage padding.

## Gate

`npm run verify` green: typecheck clean; **72** unit tests (32 new — purity, keyframe-in-effect
vs. nearest, boundary switching, caption/state co-location, clamping, modulo looping and
periodicity, progress, interpolation, timeline validation, registry integrity, and the reflow
timeline's own invariants); build; **23** Playwright tests (8 new — play/pause with the button
naming the action, scrubbing rendering the right caption and time, scrubbing pausing, keyboard
operation of the scrub, 44px controls, captions on with no `<video>`/`<audio>` anywhere,
reduced-motion not autoplaying but still scrubbing, and rendering in both themes).

One test-only trap worth knowing: React installs its own value setter on controlled inputs, so
assigning `el.value` and dispatching events by hand never reaches `onChange`. Use Playwright's
`fill()` on the scrub input.
