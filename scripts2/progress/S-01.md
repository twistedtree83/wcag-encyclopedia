# S-01 — Site origin, canonical URLs, robots.txt and sitemap.xml

**Issue:** #69  **Commit:** see `git log --grep "^S-01:"`  **Status:** shipped

## What shipped
`SITE_ORIGIN` (`https://wcagencyclopedia.com`) in `src/site/config.ts`. Every built page carries
one `<link rel="canonical">` to `SITE_ORIGIN` + its route path, and the build fails if it doesn't.
The prerender step writes `dist/robots.txt` (allow all, `Sitemap:` line) and `dist/sitemap.xml`
(every route in `ROUTES`, in order, each with a `lastmod` from git).

## Decisions made
- `src/site/crawl.ts` is the one module that builds absolute URLs: `absoluteUrl(path)`,
  `canonicalTag`, `robotsTxt`, `sitemapXml`, `pageSources`, and two checks, `canonicalProblems`
  (the ADR 0006 check) and `sitemapProblems` (the sitemaps.org 0.9 schema's rules by hand, since
  there is no XML library in the build). Pure strings, so unit tests, e2e and the prerender step
  share it. The prerender step gets it through new exports on `src/entry-server.tsx`.
- S-03 (`og:url`, `og:image`) and S-04 (JSON-LD) should build their URLs with `absoluteUrl` and
  extend `canonicalProblems`' sibling checks in the same module, not spell the origin again.
- The tag goes in a new `site.html` placeholder, `<!--@canonical-->`, filled by the prerender
  step, not through `render()`'s `head`, so S-02 and S-06 editing head rendering don't collide.
- `lastmod` is the UTC date (`YYYY-MM-DD`) of the last commit touching `pageSources(route)`:
  the guideline record file for a criterion page (`1.4.3` → `src/criteria/g1-4.tsx`), the page
  component for a fixed page (`PAGE_FILES`, a `Record<PageKind, …>` so a new kind must be added).
  The shared shell is left out on purpose. An uncommitted new file dates to today.
- CI's build job now checks out with `fetch-depth: 0`; a shallow clone would date every page to
  its single commit.
- `e2e/crawl.spec.ts` reads `dist/` (like `fonts.spec.ts`) because unit tests run before the build.
- **Test fixed on purpose:** `e2e/criterion-page.spec.ts` "loads only Figtree and Onest, from
  the site itself" failed every `<link href>` naming another origin, so it caught the canonical
  tag. It now skips `rel="canonical"`, which names production by design and loads nothing.
  S-03 and S-04 add no `<link>` elements (they're `<meta>` and `<script>`), but any later
  `<link>` to production (the S-09 feed `rel="alternate"`, say) will hit the same test.
- `CONTEXT.md` gains **Site origin**, **canonical URL** and **Crawl files**.

## Deliberately left
- The 404 page's absence from the sitemap: S-05 (it should not join `ROUTES`, or the sitemap
  must filter it).
- Blog routes in the sitemap come free when S-07 adds them to `ROUTES`; S-07 adds their source
  files to `pageSources`.
- Submitting the sitemap in Search Console: a human step after deploy (PRD-seo.md).

## Gate
`E2E_PORT=4301 E2E_WORKERS=2 npm run verify`: lint, types, unit tests, build and the full
Playwright suite, green.
