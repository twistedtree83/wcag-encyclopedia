# T-03 — App shell: header, rail, scroll-spy, principle opener, guideline section, deep links

**Issue:** #3  **Status:** shipped

## What shipped

The reference's chrome. Sticky masthead with a "You are in" strip; a left rail listing all
thirteen guidelines grouped under their four principles and tracking scroll position; chapter
openers for all four principles; guideline section headers; and the hero, "how to read a card",
and "this page obeys its own rules" prose sections.

## Decisions made

**All thirteen guidelines and all four openers render from this commit**, whether or not the
corpus reaches them. A guideline with no authored criteria renders a dashed placeholder naming
exactly which criteria are coming, read from the manifest. This means every rail link and every
opener link resolves to a real destination immediately, and it makes the thirteen content tasks
pure drop-ins — they add records to the corpus and change no structure. It also means the
placeholder can never drift from the plan, because it is generated from the same manifest the
integrity test asserts.

**Scroll-spy decides from live geometry, not from observer events.** The first implementation
picked the topmost intersecting section and was wrong: several short sections occupy the band
at once, and the earliest in document order is not the one being read. The observer now only
maintains the visible set; the choice is made by measuring that set against a reading line 120px
below the viewport top. The current guideline is **the lowest section whose head has already
crossed the reading line**, falling back to the nearest section below it when the reader is
above the first heading.

A `scroll` listener re-runs the same resolution, because scrolling *within* an already-
intersecting section fires no observer event and the rail would otherwise stick.

**The strip is `aria-hidden`, deliberately.** It updates on every scroll; announcing that would
make the page unusable with a screen reader (user story 57). Screen reader users get position
from the rail's `aria-current` and from the heading structure, both of which are stable.

**Principle grouping is carried by shape as well as hue** — square, circle, triangle, diamond,
via `PRINCIPLE_MARKS`. The accent token is applied inline from that same map rather than
hardcoded per principle in CSS, so the two can't disagree. A unit test asserts all four shapes
and all four tokens are distinct.

**Heading hierarchy:** h1 hero → h2 principle opener / section eyebrows → h3 guideline → h4
criterion. An e2e test walks every heading on the page and fails on any skipped level, so
content tasks cannot quietly break it.

## Deliberately left

- **Search and level filter** — T-05. The masthead is laid out to take them.
- **Theme toggle** — T-04.
- **Mobile drawer.** The rail currently just hides below 60rem; T-06 owns the drawer that
  replaces it, along with container queries and the viewport preview. The breakpoint is a plain
  media query for now and T-06 should expect to replace it.
- The `.guideline__pending` placeholder is intentionally plain. It disappears guideline by
  guideline as content lands.

## Gate

`npm run verify` green: `tsc --noEmit` clean; 34 unit tests; build 36 modules; **12** Playwright
tests — the six from T-02 plus rail links resolving, opener links resolving, 4 openers and 13
guideline sections present, no skipped heading levels, deep-linked card clearing the masthead,
and the rail marking the correct guideline on scroll.

Two of the new tests failed first on my own bad selectors — `#g1.4` parses `.4` as a class, so
guideline fragments are addressed as `[id="g1.4"]`. Worth knowing for any later test that
targets a criterion or guideline by fragment.
