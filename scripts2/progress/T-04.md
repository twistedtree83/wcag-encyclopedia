# T-04 — Theme: OS default, explicit override, persistence

**Issue:** #4  **Status:** shipped

## What shipped

The theme toggle in the masthead. The page opens in the reader's OS theme; an explicit choice
overrides that, persists, and wins in both directions. No flash of the wrong theme on load.

## Decisions made

**The resolution rule is one pure function, `resolveTheme(stored, systemPrefersDark)`**, so it
is testable without a browser. The rule is trivial but it is the one people get wrong: the
common bug is treating the stored value as a *dark-only* override, so a reader on a dark OS who
picks light gets dark back on their next visit. An explicit `'light'` beats a dark OS just as
an explicit `'dark'` beats a light one. There is a test for each direction.

**The theme is set before first paint by an inline script in `index.html`.** React cannot do
this — by the time a module executes, the page has already painted. The script mirrors
`resolveTheme` and sets `data-theme` on `<html>` synchronously. The CSS cascade laid down in
T-02 does the rest; nothing here touches colours.

Both copies of the rule read the same storage key, and a unit test asserts the key literal
appears in `index.html`. If they ever drift, the page renders one theme before hydration and
another after, which is exactly the flash this exists to prevent. The e2e test freezes the page
at `waitUntil: 'commit'` — before any module runs — and asserts the attribute is already right.

**Storage failures are survivable.** Private browsing and disabled storage throw on
`localStorage`; both reads and writes are wrapped. Failing to persist is acceptable, failing to
switch is not.

**A reader with no stored preference follows their OS live**, via a `change` listener on the
media query — so flipping the system theme flips the page. Once they have chosen, the listener
stops applying to them.

**The button names the action, not the state.** A button labelled "Dark" is ambiguous about
whether it means "you are in dark" or "switch to dark". It reads "Dark mode" in light and
"Light mode" in dark, and an e2e test pins that.

## Deliberately left

- The toggle sits at the end of the masthead row via `margin-left: auto`. T-05 adds the search
  and filter controls to that row and will need to place them before it; T-06 owns how the row
  behaves at 320px.
- No system/light/dark tri-state control. Two states plus "never chosen" covers it, and a third
  visible option would need a third label to be unambiguous.

## Gate

`npm run verify` green: typecheck clean; **78** unit tests (6 new — resolution in both
directions, unrecognised stored values, and the storage key matching `index.html`); build;
**29** Playwright tests (6 new — OS default, toggling and its label, persistence across reload
in both directions, no pre-paint flash, and keyboard operation with a visible focus ring).
