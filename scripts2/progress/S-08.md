# S-08 — Showing criterion examples and labs inside a post

**Issue:** #76  **Commit:** (this commit)  **Status:** shipped

## What shipped
A post can embed a criterion's existing fail and pass examples, or an existing lab, with one
line of Markdown. The post page draws them with the components its criterion page uses, links
the criterion page, and the lab hydrates and works there. Nothing a post writes can add to an
example or lab: there is no directive for one of its own.

## Decisions made
- **Syntax** (leaf directives, `micromark-extension-directive` + `mdast-util-directive`,
  devDependencies used only by `parse.ts`):
  - `::example{num="1.4.3"}`
  - `::lab{id="fade-text" num="1.4.3"}`. `num` is required on a lab too: it is the criterion the
    verdict names ("1.4.3 passes"), and the parser can only check criteria, not lab ids. The
    spec's `::lab{id="contrast"}` was an illustration; there is no lab `contrast`.
- **Parse-time checks** (with the line): unknown criterion; criterion not in `criteria`; a
  missing or extra attribute; a label `[…]`; any other `::name`; any container `:::name` ("a
  block of the post's own content"); the same example (by num) or lab (by id) twice; an embed
  before the first heading (the lab brings an h3 title and h4 steps, some examples an h3). An
  embed counts as linking its criterion, so "every `criteria` entry is linked" is met by it.
  Inline (text) directives are deliberately not enabled: `Note:this` stays text.
- **Render-time checks** (`PostBody`, fails the prerender and so the build): the lab id exists
  in the registry, and the lab lists `num` in its criteria. The registry is an
  `import.meta.glob`, which `parse.ts` can't reach from the Vite plugin. `PostBody` now takes
  `slug` as well as `nodes`, for the error message.
- **Body tree**: `PostTag` gains `example` and `lab`; `PostElement` gains `num?` and `lab?`.
  Embed nodes have no children.
- **Shared components**: `ExamplePair` (`src/components/ExamplePair.tsx`, moved out of
  `CriterionPage`) and `LabSlot` (`src/labs/shared/LabSlot.tsx`). `.lab-slot` now carries
  `data-lab="<id>"` on criterion pages too. Unit test compares the embedded markup with the
  criterion page's (ids from `useId` normalised).
- **Copy**: example embed has a lead "Broken, then fixed, from <link>: the same interface twice…";
  lab embed is followed by "A lab from <link>: a small working piece of interface…".
- **CSS**: the post body lost `.prose` (its `p` rule leaked into labs). Every `.post__body`
  rule is `:not(.embed *)`; the body's own children keep 64ch, embeds run full width.
- **e2e**: every `labCases` case has `id` (all 61 cases edited). `labCases` re-runs a
  criterion-page case on each post embedding that lab for that criterion, selector scoped to
  `.lab-slot[data-lab=id]` (`inPosts` in e2e/labs/support.ts; embeds read by
  `e2e/support/posts.ts` with `parsePost`). `e2e/blog.spec.ts` per embed: drawn, linked, link
  200; and fails if an embedded lab has no criterion-page case in e2e/labs.
- The fixture post now embeds `::example{num="1.4.11"}` and `::lab{id="fade-text" num="1.4.3"}`;
  its outline expectation became [1,2,3,3,4,4,2] (the fade lab has an h4 of its own).

## Deliberately left
- No post ships, so the post-embed e2e cases generate nothing in the committed build. I built
  once with the fixture copied into `src/blog/posts/` and ran blog.spec, fade-text lab spec
  (6 post cases), axe/reflow/focus specs filtered to the post, crawl, placeholders, share,
  fonts, retired, analytics, theme, criterion-page, live-examples, colour-check and vision lab
  specs: all green. Also confirmed an unknown lab id and an unknown criterion each fail the build.
- URL-state axe scans (`axeStates` with query URLs) are not repeated on posts; the post page's
  start state is axe-scanned in all modes by axe.spec via ROUTES. A URL-state lab embedded in a
  post reads the post's query string the same way.
- Two embeds of different criteria whose examples use the same plain `id` (e.g. `id="email"`)
  could collide on one post page; axe would catch it on the post (S-11+).
