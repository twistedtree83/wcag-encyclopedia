# T-08 — Computed contrast badges on examples

**Issue:** #8  **Status:** shipped

## What shipped

`<MeasuredRatio>`: the ratio badges on contrast examples, computed from the colours the example
actually renders. No contrast ratio is authored as a literal anywhere in the corpus.

## Decisions made

**The badge reads the live palette for the current theme and runs it through the contrast
engine.** Changing a swatch changes the badge with no content edit, and the page cannot display
a ratio it did not measure. An e2e test switches themes and asserts the numbers *change* — a
hand-typed ratio would read identically in both, so this catches a regression to literals.

**Thresholds and measurements are different things, and only one is forbidden.** A restatement
of 1.4.11 has to be able to say "3:1" — that is a constant of the standard, not a claim about
this example. What must never be authored is a ratio describing *these* colours. The test
allows WCAG's thresholds (3:1, 4.5:1, 7:1) in restatements and forbids **any** ratio in
captions, diff lines, and diff notes, which is where example-specific numbers would hide. The
1.4.11 diff's code comments lost their ratios accordingly; the badges carry them now.

**The badge states pass/fail with a glyph, a shape (square for fail, pill for pass), and a
visually-hidden "Fails:"/"Passes:" prefix** — so it reads without colour and announces
correctly.

### The bug worth remembering

The axe scan failed on the badge's own threshold text: `opacity: 0.85` composited `--pass`
against `--pass-bg` down to **4.36:1**, while the token audit measured that same pair at
5.6:1 and passed. **The token audit cannot see opacity** — it compares token values, and
opacity changes what actually lands on screen.

Fixed by deleting the opacity and taking the quieter voice from weight and size instead, which
is precisely what this page's own 1.4.3 card tells readers to do. A unit test now fails the
build on any `opacity:` declaration in the stylesheet. **Content tasks: do not fade text.** If
something needs to recede, change its weight or size, or add a token and audit it.

## Deliberately left

- `MeasuredRatio` takes tokens, not arbitrary colours. Any example needing a measured ratio
  must express its colours as audited tokens first — consistent with T-07's rule.
- Only 1.4.11 uses badges so far. 1.4.3 (T-16) is the other obvious consumer.

## Gate

rule across every record, and the no-opacity guard); build; **50** Playwright tests (2 new —
badges reporting different numbers per theme, and stating pass/fail without relying on hue).
