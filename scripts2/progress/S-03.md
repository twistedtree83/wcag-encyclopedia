# S-03 — Open Graph, Twitter cards and generated share images

**Issue:** #71  **Commit:** see `git log --grep "^S-03:"`  **Status:** shipped

## What shipped
Every built page carries the Open Graph tags (`og:type`, `og:site_name`, `og:title`,
`og:description`, `og:url`, `og:image` with its type, width, height and alt) and
`twitter:card=summary_large_image` with `twitter:image:alt`. Each points at a **share card**, a
1200×630 PNG drawn at build time into `dist/share/`: `<num>.png` per criterion page (principle
marker and name, number in accent text, name, level badge) and `site.png` for the fixed pages.

## Decisions made
- `src/site/share.ts` owns the tags (`shareTags(route)`, title and description from `pageMeta`)
  and describes each card as a `CardNode` tree (`shareCard(route)` → `{ file, alt, tree }`).
  `toSatori` turns the tree into satori's element shape; every `div` becomes a flex box.
- Cards use the dark theme's tokens (the design's default), Figtree 800/700 and Onest 400.
  satori reads no woff2, so `CARD_FONTS` names the `.woff` files in `@fontsource/*/files/`.
- satori sizes boxes content-box: the frame's width and height are 1200×630 minus its padding.
- `cardContrastProblems` (contrast engine) holds all card text to 4.5:1, with no large-text
  allowance, and marker shapes to 3:1 against the nearest background. The build fails on it.
- `openGraphProblems(html, path)` sits beside `canonicalProblems` in `src/site/crawl.ts`: each
  tag once and non-empty, `og:url` = `absoluteUrl(path)`, `og:image` a PNG under
  `SITE_ORIGIN/share/`. prerender.mjs fails the build on it; `e2e/share.spec.ts` re-runs it
  on `dist/` and reads each PNG's IHDR size.
- `render()` gained a `share` field and site.html a `<!--@share-->` placeholder after the
  canonical tag. satori and `@resvg/resvg-js` are devDependencies, imported only by
  prerender.mjs; the e2e spec fails if either, or the tags, reach `dist/assets/*.js`.
- Criterion pages are `og:type=article`, fixed pages `website`.

## Deliberately left
- Post share cards (S-07): `shareCard` gives any non-criterion route the site card. A post card
  is a new branch there and a new `file` under `share/`.
- JSON-LD (S-04) and the 404 page (S-05): the 404 page is not in `ROUTES`, so it gets no tags
  from this loop; if S-05 renders it through `render()` it should either get the site card or
  skip `openGraphProblems`.
