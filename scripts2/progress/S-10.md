# S-10 — The writing standard and the writing test

**Issue:** #78  **Commit:** (this commit)  **Status:** shipped

## What shipped
`docs/WRITING.md`, the standard for every post, test procedure and common question: voice,
banned constructions with the reason for each, substance, sources, length (900–2,500 words) and
how to name a criterion. `tests/writing.test.ts` holds every post in `src/blog/posts/` and the
`procedure` and `questions` of every criterion record to it in the verify gate. `CLAUDE.md`,
`CONTEXT.md` (Writing standard, writing test) and `docs/CONVENTIONS.md` ("Blog posts") point to it.

## Decisions made
- **Rules are data in `tests/writing.ts`** (`RULES`, `SOURCE_DOMAINS`, `WORDS`), per ADR 0007.
  Each rule has `id`, `name` (word for word as WRITING.md's table names it), `reason`, an
  `example` sentence and `find(paragraph)`. The test asserts every example fails its rule, both
  as bare prose and inside an otherwise clean post, and that WRITING.md contains every `name`.
  So adding a rule = one `RULES` entry + one table row; both are enforced.
- **Two entry points.** `postProblems(source, slug)` → `{rule, detail}[]`; `proseProblems(text)`
  for any prose (paragraphs split on a blank line). `recordProse(record)` collects every string
  in a record's `procedure` and `questions`, whatever shape S-17 gives them (a React element is
  read through `props.children` only).
- **What a post is checked for:**
  - `frontmatter` / `markdown` / `criterion-link`: `parsePost`'s own errors, mapped by text
    ("criteria is empty" and "never links its page" → `criterion-link`; `line N:` → `markdown`).
    If parsePost throws, no further checks run.
  - every banned rule over title, description and each block of the body (p, li, blockquote,
    h2–h6), code (`pre`, inline `code`) left out. The em-dash rule counts per block.
  - `criterion-link`: at least one link to `/criteria/<num>/`.
  - `criterion-name`: each criterion link's text holds its number or its exact manifest name.
  - `sources`: an h2 exactly "Sources"; every link up to the next h2 must be http(s) on
    `SOURCE_DOMAINS` (host equal or a subdomain), and at least one must be.
  - `length`: words in the body prose (code excluded, Sources included), 900–2,500.
- **Banned list** = the ticket's list plus leverage, empower, realm, tapestry, "a testament to",
  "plays a crucial role". Matching is case-insensitive with word boundaries and common
  inflections. `robust` passes only as "Robust" with "principle" or "4"/"4.x" within ~30 chars
  before / 40 after. "not just X, but Y" = `not (just|only|merely|simply) … but` within one
  clause; "it's not X, it's Y" = `(it|this|that) ('s not|is not|isn't) …[,;—–] (it|this|that)('s|is)`.
- **Three adjectives** is a heuristic: "a, b(,) and/or c" where all three are on a short list
  or end in -ive/-ous/-ful/-less/-able/-ible/-ic/-al/-ary/-ish. Noun lists pass ("colour, size
  and position"). It will flag "visual, auditory and cognitive": reword ("sight, hearing or
  thinking").
- **Fixture excluded** because the test reads `src/blog/posts/` from disk; the fixture lives in
  `tests/fixtures/`. The passing sample post is built in the test (`post()`), ~1,000 words.
- With no posts yet, "every post" runs one empty placeholder case; with no `procedure` or
  `questions` on any record, the 55 record cases pass vacuously until S-17.

## Deliberately left
- S-17 adds `procedure` and `questions` to the record type; the record cases here already read
  them. S-17's "the writing test covers both fields" needs only a check that they are non-empty
  strings the test reaches (e.g. add a case that a banned phrase in a real record fails).
- British spelling, a concrete example, and source accuracy are review-only (WRITING.md marks
  what is tested).
- S-08 directive nodes: the walkers tolerate elements without `children`.
- Links to posts from posts (`/blog/<slug>/`) are still rejected by parsePost (S-07).
