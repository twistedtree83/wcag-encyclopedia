# S-16 — Post: How to test a page in 15 minutes

**Issue:** #84  **Commit:** see the PR (branch `post/s-16-15-minute-test`)  **Status:** shipped, waiting on the owner's approval of its PR

## What shipped
One post, `src/blog/posts/test-a-page-in-15-minutes.md` (`/blog/test-a-page-in-15-minutes/`),
published 2026-11-28. It is an order of manual checks for one page, timed to 15 minutes: an
automated scan (Lighthouse or Firefox's Accessibility panel), then title, language and moving
content, then keyboard, zoom, contrast and colour, images and structure, and one form. It ends
with what the pass leaves out. It embeds the `skip-link` lab for 2.4.1 and links the 4.1.2 page
for its "How to test" section (S-17).

## Decisions made
- Slug `test-a-page-in-15-minutes`: names the topic, no version or year, so it never needs to change.
- Criteria (20): 1.1.1, 1.3.1, 1.4.1, 1.4.2, 1.4.3, 1.4.4, 1.4.10, 1.4.11, 2.1.1, 2.1.2, 2.2.2,
  2.4.1, 2.4.2, 2.4.3, 2.4.7, 2.4.11, 3.1.1, 3.3.1, 3.3.2, 4.1.2. Each is one the post asks the
  reader to check. 2.4.6 and 4.1.3 were left out to keep "Further reading" to pages the post
  really tests.
- Tools named are all free and built into the browser: Chrome DevTools (Lighthouse, the
  contrast tooltip and colour picker, CSS Overview) and Firefox's Accessibility panel (Check for
  issues, Show Tabbing Order, Simulate). NVDA and VoiceOver are named as the next step. The
  site's own `/colour-check/` page is linked.
- 1.4.1 links: W3C's current G183 accepts 3:1 contrast with the surrounding text on its own (no
  hover or focus cue). The post says so and recommends an underline as the simpler fix.
- Contrast figures (#8a8a8a 3.45:1, #767676 4.54:1, #949494 3.03:1, each on white) computed with
  the WCAG relative-luminance formula.
- Facts checked against W3C Easy Checks, Selecting Evaluation Tools, WCAG 2.2 conformance
  requirements (full pages, complete processes), the Understanding pages for 1.4.2, 2.2.2, 2.4.1,
  2.4.11, 2.1.2, 1.4.4, 1.4.10, 1.4.3, 1.4.1, technique G183, and the Chrome and Firefox
  DevTools docs. "55 Level A and AA criteria in WCAG 2.2" follows the S-13 post.
- Test fixes, deliberate, none weakened:
  - `tests/criterionPage.test.tsx` section order expects "Further reading" when
    `postsAbout(num, POSTS)` is non-empty (same as PRs #91–#93).
  - `tests/share.test.ts` counts one card per post (same as PRs #91–#93).
  - New here: the S-17 test "puts How to test and Common questions … on 4.1.2 and 4.1.3" listed
    the h2s exactly, with no "Further reading". This post lists 4.1.2, so it now expects
    "Further reading" on the same condition. PRs #91–#93 branched before S-17 merged and also
    list 4.1.2, so each will hit this when merged on top of `seo`.
