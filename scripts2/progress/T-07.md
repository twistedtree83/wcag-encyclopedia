# T-07 — Markup-diff card variant, proven on 1.4.11

**Issue:** #7  **Status:** shipped

## What shipped

The second card variant: a code diff beneath the fail/pass pair, for criteria whose point is
code rather than perception. Proven on 1.4.11 Non-text Contrast, whose fix is a single
border-colour declaration. This unblocks all thirteen content tasks.

## Decisions made

**The gutter glyph is real text, not a pseudo-element.** `-` and `+` live in a `.diff__gutter`
span inside the line, so they survive colour being removed, high-contrast mode, and copy-paste.
Changed lines additionally carry a visually-hidden `removed:` / `added:` prefix, so a screen
reader user gets the same information a sighted reader gets from the tint. Tint alone would be
the page failing 1.4.1 on the very card that teaches 1.4.11.

**Diff text is authored without its own `+`/`-` markers** — the gutter renders them. A unit test
enforces this, because authoring them inline doubles the marker and is an easy mistake to make
when pasting a real diff.

**`TOKEN_PAIRS` now carries `expect: 'pass' | 'fail'`.** This is the significant change and
later content tasks should use it.

Example colours have to be tokens (T-02's finding), but a *failing* example's colour
deliberately does not meet its threshold — so it cannot simply be added to an audit that
asserts everything passes, and leaving it out returns us to the unaudited literals that caused
the T-02 bug. Declaring the expectation solves both: `expect: 'fail'` asserts the colour
**genuinely fails**. If someone later lightens the palette and the "bad" border quietly starts
clearing 3:1, the build breaks — because at that point the example has stopped demonstrating
anything. A fail example must break exactly what it claims, in both directions.

**1.4.11's swatches are theme-aware, and that matters more than it looks.** The design file
renders this example on hardcoded white. Ported naively, `#EBEBEB` on a dark panel becomes
*high* contrast — the fail example would demonstrate the opposite of its lesson in dark mode.
The four swatches preserve the relationship instead:

| | light | dark |
|---|---|---|
| `swatch-border-weak` | `#EBEBEB` — 1.1:1 | `#2E2E28` — 1.2:1 |
| `swatch-border-strong` | `#6A6A6A` — 5.4:1 | `#8C8779` — 4.7:1 |

**Content tasks: never hardcode a colour in an example.** Add a `swatch-*` token pair, declare
what it is expected to do, and let the audit hold you to it.

**The diff is a focusable scrollable region.** The axe scan caught this at 320px, where the
diff actually overflows: `overflow-x: auto` creates a scroll container, and without
`tabindex="0"` a keyboard user cannot reach it — so they cannot read the end of a long line.
It now takes focus, carries `role="region"` and a name from its title, and shows the global
focus ring. Any future scrollable block needs the same treatment.

## Deliberately left

- Guideline 1.4's remaining criteria — 1.4.10 is T-09's (it needs the demo), the other six are
  T-16's.
- The diff renders no syntax highlighting, deliberately: colour-coded tokens would be another
  hue-only signal to justify, for no teaching benefit.

## Gate

`npm run verify` green: typecheck clean; **40** unit tests (6 new, covering diff completeness
and the no-inline-marker rule); build; **15** Playwright tests (3 new: glyph markers and
screen-reader prefixes present, long lines scrolling inside the diff rather than the page at
320px, and the diff being keyboard-reachable with a visible focus ring).
