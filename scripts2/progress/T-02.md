# T-02 — Walking skeleton: build, token palettes, one criterion card, contrast audit, CI

**Issue:** #2  **Status:** shipped

## What shipped

A deployable static site that renders criterion 1.4.1 Use of Color as a card, with the build,
test, and CI machinery every later task inherits. Vite + React + TypeScript in strict mode;
both theme palettes defined as data and emitted as CSS custom properties at build time; a pure
contrast engine; and `npm run verify` gating types, unit tests, build, and an axe-core scan.

## Decisions made

**React.** The design file's own runtime compiles to React, and the interactive work still
ahead — filter, theme toggle, viewport preview, and especially the demo player's scrub — is
genuinely stateful. Components stay thin; all logic lives in pure modules that test without a
DOM.

**Tokens are emitted at build time, not runtime.** `vite.config.ts` carries a small
`transformIndexHtml` plugin that inlines `tokensCss()` into `<head>`. Custom properties are
therefore present before first paint — no flash of an unthemed page — and `tokens.ts` stays the
only place a colour is written down. T-04 only needs to set `data-theme` on the root; the
cascade is already built for it: `:root` is light, the `prefers-color-scheme` block is guarded
with `:not([data-theme="light"])`, and `:root[data-theme="dark"]` wins last. An explicit choice
beats the OS setting in both directions.

**Four colours in the design fail their own contrast requirement.** The design file is the
visual source of truth, but CONTEXT.md says page-obeys-its-own-rules outranks visual fidelity,
so these were changed rather than exempted:

| token | design | now | was | needed |
|---|---|---|---|---|
| light `ink3` | `#777263` | `#6B6657` | 4.4:1 on `bg` | 4.5:1 |
| light `rule2` | `#B4AC99` | `#87806F` | 2.1:1 on `bg` | 3:1 |
| dark `rule2` | `#514F47` | `#787368` | 2.0:1 on `panel` | 3:1 |

`light p1` was also adjusted and then reverted — `#8A5300` measures 5.9:1 and never needed
changing. Where the design already complies, it is followed exactly.

**`TOKEN_PAIRS` is the audit's scope, and it is a manual list.** 42 pairs × 2 themes = 84
assertions. Auditing the cartesian product would be mostly meaningless combinations; instead
every pairing that actually occurs is declared with a `where` string and a `kind` selecting the
threshold. **When a component introduces a new pairing, add it here** — an unlisted pairing is
an untested pairing. A guard test asserts all three ink levels are covered against all three
surfaces so the common case cannot be forgotten.

**Colours inside examples are tokens too.** The axe scan caught the 1.4.1 fail example at
3.09:1 in dark mode: it hardcoded `#1668C4`, which is fine on white and fails on the dark
panel. That example exists to fail 1.4.1 (hue as the only signal) — failing 1.4.3 as well
muddies what it teaches. It is now `--swatch-link`, theme-aware and in `TOKEN_PAIRS`. **A fail
example must break exactly the criterion it illustrates and nothing else.** Later content tasks
should follow this: no literal hex in example markup unless the specific value is the point.

**Manifest vs. corpus.** `manifest.ts` declares the closed set of all 55 Level A/AA criteria
and is fully asserted from day one — count, the 20/20/13/2 principle split, the absence of
4.1.1, uniqueness, and guideline resolution. The corpus grows toward it. Every authored record
must appear in the manifest with a matching level and guideline, so a typo'd number or
mislabelled level fails the gate immediately.

**Level badges differ in shape, glyph, and label.** A is a filled square (■), AA an outlined
pill (◐), AAA a double-ruled pill (◈). Fail/pass frames likewise: square glyph container for
fail, circle for pass, plus the words. Remove all colour and both distinctions survive.

## Deliberately left

- **Corpus-equals-manifest.** The integrity test asserts `corpus ⊆ manifest` today. The
  equality assertion belongs to **T-25**, the last content task, which should tighten it once
  all 55 records exist. It is absent rather than disabled — nothing here needs un-skipping.
- **Header controls, rail, scroll-spy, principle openers** — T-03. `App.tsx` deliberately
  renders no navigation it cannot honour yet.
- **Theme toggle UI** — T-04. The cascade is ready; only the control and its persistence are
  missing.
- **`.frame__body` responsive behaviour below 320px** — T-06 owns container queries.
- Guideline 1.4's other eight criteria — T-07 (1.4.11), T-09 (1.4.10), T-16 (the rest).

## Gate

`npm run verify` green:

- `tsc --noEmit` — clean under `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`
- `vitest run` — 34 passed across contrast (9), tokens (8), criteria (17)
- `vite build` — 36 modules, 202 kB JS / 64 kB gzip
- `playwright test` — 6 passed: axe clean in light, dark, and at 320px; no horizontal scroll at
  320px; skip link first in tab order; every link has a focus outline

Tightest contrast margin in the palette is +0.34 over threshold (dark `rule2` on `panel2`,
3.3:1 against a 3:1 requirement).
