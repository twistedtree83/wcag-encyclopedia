## Decisions made

**2.1.1's pass example is a real, focusable `<button>`** rather than a picture of one — so the
reader can Tab to it inside the card and watch it take the focus ring. The fail example is a
`<span>` that deliberately cannot. The diff spells out the four things a `div` needs before it
is equivalent (`role`, `tabindex`, and handlers for *both* Enter and Space), which is the honest
argument for using the element.

**2.1.2 makes the point that trapping focus is not the bug.** A modal *should* cycle focus; the
requirement is that the cycle has a documented exit. The pass example points at this page's own
navigation drawer, which gets Escape and focus restoration free from native `<dialog>` — the
same reasoning recorded in T-06.

**2.1.4 leads with the speech-input case**, because "who does this hurt" is genuinely
non-obvious for single-key shortcuts: dictating a sentence fires them mid-word. The pass example
lists all four remedies and notes that only the settings toggle also helps someone prone to
accidental keypresses.
