# S-07 — Blog: posts, the blog index and the post page

**Issue:** #75  **Commit:** (this commit)  **Status:** shipped

## What shipped
Posts are Markdown files in `src/blog/posts/<slug>.md`, compiled at build time by the `posts`
Vite plugin into plain data and rendered to `/blog/<slug>/`, with the index at `/blog/`. Both
join `ROUTES` (so the sitemap, canonical, share cards, headMeta and the axe scan cover them),
"Blog" is in the header nav, and each post carries a `BlogPosting` and its own share card. The
built site ships no post yet; a fixture post exists only in tests.

## Decisions made
- **Pipeline.** `src/blog/parse.ts` (`parsePost(source, slug)`) uses `mdast-util-from-markdown`
  and `yaml` (devDependencies) and is imported only by `src/blog/plugin.ts`, which
  `vite.config.ts` loads. `<slug>.md` compiles to the whole post, `<slug>.md?meta` to the
  frontmatter alone. Consumers: `src/blog/posts.ts` (`POSTS`, `postMeta`: every `?meta`, eager),
  `src/blog/bodies.ts` (`postFor`: every full post, imported only by entry-server),
  `entry-client.tsx` (lazy glob: loads only the current post before `hydrateRoot`).
  `e2e/blog.spec.ts` fails if parser strings reach `dist/assets`.
- **Body tree.** `PostNode` in `src/blog/post.ts`: text or `{ tag, children, to?, href?, start? }`.
  `PostBody.tsx` draws it. What a body may hold is the `NODES` table in `parse.ts`; any other
  mdast node (raw HTML, image, reference link, and today any directive) fails the build with the
  line. **S-08**: enable `micromark-extension-directive` + `mdast-util-directive` in
  `fromMarkdown(..., { extensions, mdastExtensions })`, add `leafDirective` to `NODES` producing
  a new JSON node (e.g. `{ tag: 'example', num }`), and a branch in `PostBody` that renders the
  existing criterion example / lab component. Labs will then hydrate on post pages because the
  client renders the same `PostBody`.
- **Links.** A site link is written from the root ending in `/` (`/criteria/1.4.3/`) and becomes
  `to: 'criteria/1.4.3/'`, drawn relative with `href()`. Criterion links must be in `criteria`;
  every `criteria` entry must be linked (I added this direction too: `criteria` means "the
  criteria it discusses", which S-09's Further reading relies on). Links to the site origin in
  full, relative links and missing trailing slashes fail. Post-to-post links (`/blog/<slug>/`)
  are not accepted yet (only `PATHS` and criterion pages): add them when a post needs one.
- **Headings.** Body starts at `##`; `#` or a skipped level fails the build. Unit "outline test"
  (`tests/blogPage.test.tsx`) checks one h1 and no skips on the post page and index.
- **Frontmatter** fields are exactly `title, description, published, updated?, criteria`;
  unknown keys fail (so `author` can't creep in). The post title is the page title as written
  (no brand suffix), so it must be 30–65 characters and the description 70–160: headMeta
  enforces this because posts are in `ROUTES` under vitest.
- **Dates.** Page and `BlogPosting` use frontmatter `published` / `updated ?? published`;
  sitemap lastmod is git (`pageSources(post) = src/blog/posts/<slug>.md`; blog index =
  `src/pages/BlogPage.tsx` + `src/blog/posts`).
- **Routes without Vite.** `src/blog/slugs.ts` uses `import.meta.glob` in a `try`; the e2e specs
  import `ROUTES` without Vite, where it throws, so it reads the folder with
  `process.getBuiltinModule('node:fs')` (Node 22.3+; no import, so nothing Node-only is bundled).
- **JSON-LD.** `BlogPosting` (headline, description, url, mainEntityOfPage, dates, organisation as
  author and publisher, `image` = the post's share card, `about` = a `DefinedTerm` with `url` per
  criterion). `TYPES.post = [BlogPosting, BreadcrumbList]`, `TYPES.blog = [BreadcrumbList]`.
  Shared article checks moved into `article()` in jsonLd.ts.
- **Share cards (merged with S-03).** Posts get `share/blog-<slug>.png` (title, "Blog",
  date, criteria) and `og:type` article; the blog index uses the site card.
- **Fixture post.** `tests/fixtures/posts/fixture-contrast-thresholds.md`, loaded by
  `tests/fixturePost.ts`. `tests/blogBuild.test.ts` `vi.mock`s `src/blog/slugs`, `posts` and
  `bodies` with it to test a post through `ROUTES`, `render`, `structuredData`, share card.
- Breadcrumb: Home / Blog / post title. Nav order: Home, Criteria, Colour check, Blog, About.

## Deliberately left
- Directives `::example` / `::lab`: S-08. Feed and "Further reading": S-09 (read `POSTS` and each
  post's `criteria`; the feed needs full content, so read `bodies.ts` at build time and render
  `PostBody` to static markup). Writing test over every post: S-10 (walk
  `import.meta.glob('../src/blog/posts/*.md', { query: '?raw' })` or read the folder, and reuse
  `parsePost` for the frontmatter).
- No post page has been axe-scanned in the committed build (there is no post). I built once with
  the fixture copied into `src/blog/posts/` and ran axe, the blog spec, crawl, placeholders,
  fonts, retired, analytics and theme specs on it: all green. S-11 gets the real scan.

- `e2e/criterion-page.spec.ts` lists the main nav links; updated it to include Blog (the ticket
  adds it), not a weakened test.
- Merged with S-05: `blog` and `post` sit beside `not-found` in every `Record<PageKind,…>`. The
  404 page's "Read the blog" link is followed by `e2e/blog.spec.ts` and reaches the index (200).
