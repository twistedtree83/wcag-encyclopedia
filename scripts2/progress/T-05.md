# T-05 — Filter and search: level filter, text search, result count

**Issue:** #5  **Status:** shipped

## What shipped

Search and the conformance-level filter in the masthead, over a pure filter engine. Level is
single-select (Everything / Level A / Level AA), search matches criterion number and name, and
the two compose. A count line reports how many criteria are showing out of the total.

## Decisions made

**The engine is `(criteria, query) → criteria`, with no DOM and no component state.** All the
rules — level, text, composition, counts, and the summary wording — are pure functions in
`catalog/filter.ts` and tested directly. `Controls.tsx` has no logic worth testing; it renders
a `Query` and calls back with a new one.

**Filtered-out criteria are not rendered at all**, rather than hidden with CSS. Absent from the
DOM means absent from the accessibility tree, so a screen reader user and a sighted user see
exactly the same set. Hiding visually while leaving them exposed to assistive technology is the
usual bug here and it is worse than not filtering at all.

**The count is a live region (`role="status"`, `aria-live="polite"`).** This is the deliberate
counterpart to the "You are in" strip being `aria-hidden`: the strip changes on every scroll
and would chatter, while the count changes only when the reader operates a control, and it is
the *only* feedback that the control did anything. A screen reader user typing into the search
box would otherwise get silence.

**A guideline with no matches says which kind of nothing it is.** "Not yet documented — 5
criteria to come" and "No criteria in 1.4 match the current filter" are different facts, and
showing the first when the second is true would misreport the project's progress. The section
picks between them on whether the guideline has *authored* criteria, not filtered ones.

**Level filter offers no AAA option**, matching the design and the manifest: AAA is not part of
the closed set, and a filter for it would usually return nothing.

## Deliberately left

- The controls row currently wraps at narrow widths but is not yet collapsed into the drawer —
  **T-06** owns that, and should move search and the level filter into the drawer at 320px per
  its acceptance criteria.
- No URL persistence of the query. Deep links address criteria, not filter states.
- Search does not match restatement or example text, per the PRD's out-of-scope list.

## Gate

`npm run verify` green: typecheck clean; **91** unit tests (13 new, covering the engine
directly: level selection, case-insensitive and partial matching on both name and number,
whitespace handling, composition, count/list agreement, and all three summary wordings); build;
**36** Playwright tests (7 new: Level A removing AA cards from the DOM, `aria-pressed` state,
search by name and by number, the count matching the rendered card total, the live region
attributes, the empty-result message, and the two placeholder messages being distinguished).

Test-only trap: `getByRole('button', { name: 'Level A' })` also matches "Level AA" — these
accessible names are prefixes of each other, so `exact: true` is required.
