# L-19 — Forms: 3.2.2, 3.3.3 and 3.3.4

**Issue:** #59  **Commit:** see `git log --grep "L-19:"` on `labs`  **Status:** shipped

## What shipped
3.2.2, 3.3.3 and 3.3.4 have live examples on both stages and a lab each. On 3.2.2 the Broken checkout reloads for the chosen country (inside the example: a depicted address bar changes and the typed name empties); the Fixed one only chooses, and an "Update address format" button changes the postcode field in place. On 3.3.3 both forms have rejected "03/27/1995" with the error tied to the field; the Broken one says "Invalid date", the Fixed one says the order with an example, and accepts a corrected date. On 3.3.4 the Broken button deletes 1,240 records at once; the Fixed one asks first (Cancel or confirm) and then offers Undo. Labs: "Try it: change the country" (navigate on change vs wait for Go), "Try it: suggest the fix" ("Invalid input" vs "Use DD/MM/YYYY, for example 05/03/2026"), "Try it: catch the wrong payment" (no safeguard, a review step with a way back, or an undo, on a £2,500.00 payment that should be £250.00).

## Decisions made
- No new instrument, key or `StageEvent`. All three use `announcement-log`. 3.3.4's outcomes are `role="status"` text, so L-11's status events put them in the log on both stages.
- 3.2.2 uses a radio group for the country, not a `<select>`. Simulated Space activates radios (`el.click()`), and a select can't be changed through the bar. The lab's mock still depicts a select, because the reader works it through the controls beside it.
- The labs start failing. Their verdicts judge the design the reader chose (mode, message, safeguard), so they hold before the first submit or payment.
- Models: `src/labs/onInput.ts`, `errorSuggestion.ts` (it also has `isDayMonthYear`, which the Fixed 3.3.3 form uses), and `errorPrevention.ts`. The transition functions return `{ state, said }`. Unit tests: `tests/formsLabs2.test.tsx`.
- The 3.3.4 lab and the Fixed 3.3.4 example replace the pressed button at the next stage. Focus moves to the first button there, but only after the reader pressed one, so nothing takes focus on load.
- CSS: swatch.css "Forms: on input, error suggestion and error prevention (L-19)". `.addrbar` is a depicted address bar, `.lform__set` is a radio group inside `.lform`, and `.pay__btns` is a row of buttons. No breakpoint overrides were needed.

## Deliberately left
- Real arrow keys work on the Fixed 3.2.2 radios. The bar has no arrow key, so on both stages a choice is made with Tab then Space.
