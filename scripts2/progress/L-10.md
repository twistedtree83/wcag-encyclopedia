# L-10 — Titles, link purpose and headings: 2.4.2, 2.4.4 and 2.4.6

**Issue:** #50  **Commit:** see `git log --grep "L-10:"` on `labs`  **Status:** shipped

## What shipped
2.4.2, 2.4.4 and 2.4.6 have live examples on both stages and a lab each. Three new input-bar keys read the example the way a screen reader user skims it: "Switch tab" says the next drawn browser tab's title, "List the links" and "List the headings" say the example's links or headings out of context. The labs: "Try it: title the page" (empty, generic or descriptive title, heard as a tab switch), "Try it: name the links" (link text and the sentence before it, heard as a links list), "Try it: write the headings" (headings and a field label, heard as a headings-and-fields list).

## Decisions made
- **Lists:** `src/live/lists.ts`. `listOf(lines, 'links' | 'headings' | 'outline')` filters announcement-log lines by role word (`outline` = headings and edit-text fields). `tabSwitchLine(title, address)` says the title, or the address when the title is empty. Unit tests in `tests/srLists.test.ts`.
- **Keys:** `SimKey` gained `switch-tab`, `links`, `headings`. All three push a `read` event (its comment now covers a screen reader's own readings), so no new `StageEvent` member and no instrument change. `switch-tab` steps over `[data-sim-tab]` elements in the example. It marks the current tab with `data-sim-on` in the DOM; that is the drawn cursor, on both stages. The CSS outline uses `--focus` and transitions colour only.
- **2.4.4 is judged in context.** A vague link passes when the sentence in the same list item names its destination. That is the WCAG reading; reading the link text alone is 2.4.9 (AAA). The lab's links list still says "Read more" for those links, and its announcement says so.
- **Labs start failing** (`startsFailing` in `e2e/labs.spec.ts`): generic title, lone "Read more" links, and vague headings plus a vague label. They are not flagships and have no URL state.
- `Choice` is now exported from `NameRoleValueLab.tsx`, as in L-09, and all three labs reuse it. Each lab has its own pure model (`pageTitle.ts`, `linkPurpose.ts`, `headingsLabels.ts`), tested in `tests/titlesLinksHeadings.test.tsx` against hand-written lines.
- Live 2.4.4 links point at made-up report paths. A click on the list is `preventDefault`ed, so a real Enter on the Fixed stage stays on the page.
- Live 2.4.6 headings are real `h3`/`h4` (under the page's "Broken, then fixed" `h2`), plus a labelled text field so Tab has a stop. The lab's depicted page uses `h4`/`h5`, nested under the lab's `h3`. It is aria-hidden, but `criterionPage.test.tsx` counts the page's `h2`s in the pre-rendered markup, and a mock `h2` broke that anatomy check.

## Deliberately left
- **Content question for a human:** the static (and live) 2.4.4 *Broken* example is "Annual report 2025 — read more" in one item. Strictly, that passes 2.4.4 in context and fails only 2.4.9. Its caption and note stay true, but the record could show links with no context. Not changed here; it is corpus content, not lab work.
- 2.4.2's live example has only "Switch tab" (the tabs are depicted browser chrome, not Tab stops).
