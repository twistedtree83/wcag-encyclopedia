    The four principles of WCAG

    Each principle splits into guidelines, and each guideline into the criteria you test against. The shape beside each name survives greyscale.

    If you can't perceive it, it isn't there for you.

    Information and interface components must be presentable in ways every user can sense. Text that can be read aloud or enlarged; contrast that survives a bright room; structure that survives losing the layout.

    1.4.3

    Contrast (Minimum)

    AA

    Body text needs at least 4.5:1 against its background. Text at 24px, or 18.66px and bold, needs 3:1. Measure it rather than judging by eye — a screen at full brightness in a dim room is the most forgiving possible viewing condition, and it is the one you are designing in.

    Showing 55 of 55
    Guideline 1.1

    Text Alternatives

    1.1.1Non-text ContentA

    Anything that is not text — an image, an icon, a chart, a video thumbnail — needs a text equivalent that serves the same purpose. Decoration needs an empty alt so screen readers skip it. The test is not "is there alt text" but "would someone who cannot see this end up knowing the same thing".

    ✕ FailAlt text exists, and tells the reader nothing.
    ✓ PassEach image is described by what it is for, not by what it is.
    Guideline 1.2

    Time-based Media

    1.2.1Audio-only and Video-only (Prerecorded)A

    A recording with only sound needs a transcript. A recording with only pictures needs either a transcript or an audio track describing it. Whichever sense the recording requires, offer the same content to someone who cannot use it.

    ✕ FailA podcast episode published as audio and nothing else.
    ✓ PassA full transcript sits beneath the player.
    1.2.2Captions (Prerecorded)A

    Prerecorded video with sound needs captions: the dialogue, who is speaking, and the sounds that carry meaning. Auto-generated captions count only once someone has corrected them.

    ✕ FailAuto-captions, uncorrected.
    ✓ PassCorrected captions, with speakers and meaningful sound.
    1.2.3Audio Description or Media Alternative (Prerecorded)A

    If the picture carries information the soundtrack does not, offer that information some other way — either an audio description track or a text alternative telling the whole story. Captions do not cover this: they carry what was said, not what was shown.

    ✕ FailThe soundtrack alone does not carry the demonstration.
    ✓ PassA text alternative describes the action, not just the dialogue.
    1.2.4Captions (Live)AA

    Live video with sound needs live captions. Real time, as it happens — a transcript published afterwards is a different thing and does not satisfy this.

    ✕ FailCaptions promised for "later today".
    ✓ PassCaptions appear during the broadcast.
    1.2.5Audio Description (Prerecorded)AA

    At AA the text alternative is no longer enough on its own: prerecorded video needs an actual audio description track, narrating the visual information into the gaps in the dialogue.

    ✕ FailA described transcript, but no described audio track.
    ✓ PassA selectable audio description track.
    Guideline 1.3

    Adaptable

    1.3.1Info and RelationshipsA

    Structure you can see has to exist in the markup too. Headings marked up as headings, lists as lists, table headers as table headers, labels tied to their fields. Strip the stylesheet: if the relationships vanish, they were never really there.

    ✕ FailStyling stands in for structure.
    ✓ PassThe same appearance, built from real elements.
    1.3.2Meaningful SequenceA

    When the order of the content matters, the reading order in the markup has to match. CSS can move things around the screen; it does not move them in the document, and the document is what a screen reader and a keyboard follow.

    ✕ FailThe visual order and the document order disagree.
    ✓ PassDocument order matches what is on screen.
    1.3.3Sensory CharacteristicsA

    Instructions cannot depend on shape, size, position, or sound alone. "The button on the right" means nothing to someone listening to the page, and nothing on a phone where it is now underneath.

    ✕ FailThe instruction relies on where things happen to sit.
    ✓ PassThe instruction names the thing.
    1.3.4OrientationAA

    Do not lock the screen to portrait or landscape unless the orientation is essential — a piano keyboard, a cheque scanner. Someone whose wheelchair mount holds their phone sideways cannot simply turn it.

    ✕ FailThe app refuses to work sideways.
    ✓ PassThe same content reflows to whatever shape it is given.
    1.3.5Identify Input PurposeAA

    Fields collecting the user’s own information — name, email, address, phone — need to say which is which in the markup, via autocomplete. That is what lets a browser fill them, and what lets assistive tools show familiar icons or wording instead of yours.

    ✕ FailNothing tells the browser what these fields are for.
    ✓ PassEach field declares its purpose from the standard list.
    Guideline 1.4

    Distinguishable

    1.4.1Use of ColorA

    Colour can carry meaning, but never on its own. If removing all colour from the screen would lose information, add a shape, a label, an underline, or an icon.

    ✕ FailHue is the only signal.
    ✓ PassA persistent underline was added.
    1.4.11Non-text ContrastAA

    The parts of a control that tell you it is a control — the input’s edge, the checkbox box, the focus ring, the chart key — need 3:1 against whatever sits behind them.

    ✕ FailThe field and checkbox edges vanish; only the placeholder hints anything is editable.
    ✓ PassOne border colour, changed on every control at once.
    1.4.10ReflowAA

    At 320 CSS pixels wide, content must not require scrolling in two directions. Same content, one column, no horizontal scrollbar.

    ✕ FailFixed 110px columns force a horizontal scrollbar — two-direction scrolling.
    ✓ Passminmax(0, 1fr) replaced the fixed track width.
    1.4.2Audio ControlA

    If sound plays automatically for more than three seconds, there has to be a way to stop it — a control on the page, not just the operating system volume. Screen reader users cannot hear their own screen reader over it.

    ✕ FailAutoplaying audio with no control on the page.
    ✓ PassIt does not autoplay — and if it must, a stop control comes first.
    1.4.3Contrast (Minimum)AA

    Body text needs at least 4.5:1 against its background. Text at 24px, or 18.66px and bold, needs 3:1. Measure it rather than judging by eye — a screen at full brightness in a dim room is the most forgiving possible viewing condition, and it is the one you are designing in.

    ✕ FailHierarchy built by fading text out.
    ✓ PassHierarchy moved from lightness to weight and scale.
    1.4.4Resize TextAA

    Text has to survive being enlarged to 200% without losing content or function. That means no fixed pixel heights around text, and no boxes that clip when their contents grow.

    ✕ FailA fixed-height box clips its own text when enlarged.
    ✓ PassThe box grows with its contents.
    1.4.5Images of TextAA

    Use real text, not a picture of text. Pictures of text do not reflow, do not respond to a reader’s font or colour settings, blur when enlarged, and cannot be selected, searched, or translated. Logos are exempt.

    ✕ FailA headline exported as an image.
    ✓ PassThe same headline as live text.
    1.4.12Text SpacingAA

    A reader must be able to increase line height to 1.5×, paragraph spacing to 2×, letter spacing to 0.12em, and word spacing to 0.16em without losing content. People with dyslexia and low vision use exactly these overrides.

    ✕ FailLoosened spacing pushes text out of a rigid container.
    ✓ PassThe container is sized by its contents.
    1.4.13Content on Hover or FocusAA

    Anything that appears on hover or focus — a tooltip, a popover, a dropdown — has to be dismissable without moving the pointer, stay visible while the pointer travels into it, and remain until it is dismissed or stops being relevant.

    ✕ FailThe tooltip vanishes before it can be read or reached.
    ✓ PassHoverable, dismissable, and persistent.
    Guideline 2.1

    Keyboard Accessible

    2.1.1KeyboardA

    Everything the interface can do must be doable from a keyboard. Not "most things", and not "there is an alternative path" — every control, every menu, every drag.

    ✕ FailA div pretending to be a button.
    ✓ PassA real button element.
    2.1.2No Keyboard TrapA

    If focus can get into something, it has to be able to get out using the keyboard alone. A trap does not merely inconvenience a keyboard user — it ends their session, because there is nothing else they can do.

    ✕ FailA hand-rolled focus trap with no way out.
    ✓ PassThe loop has an exit.
    2.1.4Character Key ShortcutsA

    A shortcut bound to a single letter, number, or symbol must be switchable off, remappable, or active only while the relevant control has focus. Speech-input users trigger these constantly just by talking.

    ✕ FailSingle-key shortcuts, always listening.
    ✓ PassScoped to focus, or remappable, or off.
    Guideline 2.2

    Enough Time

    2.2.1Timing AdjustableA

    If something is on a timer, the reader must be able to turn it off, adjust it to at least ten times the default, or extend it — with at least twenty seconds’ warning and a simple action to get more time. Real-time events and hard security limits are exempt.

    ✕ FailSession ends without warning, taking the form with it.
    ✓ PassA warning, an extension, and the work preserved.
    2.2.2Pause, Stop, HideA

    Anything that moves, blinks, scrolls, or auto-updates for more than five seconds needs a way to pause, stop, or hide it — provided it runs alongside other content. Motion in the periphery is genuinely disabling for people with ADHD, vestibular disorders, or low vision using magnification.

    ✕ FailA carousel that advances on its own, with no control.
    ✓ PassA pause control, present before the motion starts.
    Guideline 2.3

    Seizures & Physical Reactions

    2.3.1Three Flashes or Below ThresholdA

    Nothing may flash more than three times per second, unless the flashing area is very small or the flash is low-contrast. Red flashes are held to a stricter limit, because saturated red triggers photosensitive seizures at intensities other colours do not.

    ✕ FailA full-width banner strobing several times a second.
    ✓ PassThe attention is drawn without flashing.
    Guideline 2.4

    Navigable

    2.4.1Bypass BlocksA

    Give people a way past the things that repeat on every page. A skip link is the usual answer; real landmarks and a sane heading structure also count, because screen reader users navigate by those.

    ✕ FailForty links before the article, on every page.
    ✓ PassOne link, first in the tab order.
    2.4.2Page TitledA

    Every page needs a title that describes it. It is the first thing a screen reader announces, and the only thing distinguishing twenty open tabs or twenty history entries.

    ✕ FailThe same title on every page.
    ✓ PassSpecific first, site name last.
    2.4.3Focus OrderA

    Focus has to move in an order that preserves meaning. Usually that means source order — and when something opens on top, like a dialog, focus goes into it and comes back out where it started.

    ✕ FailA dialog opens and focus stays behind it.
    ✓ PassFocus follows the dialog in and back out.
    2.4.4Link Purpose (In Context)A

    What a link does has to be clear from its text, or from the sentence, list item, cell, or paragraph around it. Screen reader users often pull up a list of every link on the page, where that surrounding context is gone.

    ✕ FailEleven links that all say the same thing.
    ✓ PassThe link text names its destination.
    2.4.5Multiple WaysAA

    Offer more than one route to each page — navigation plus search, or a sitemap, or an index. People navigate differently; some scan structure, others go straight to search. Steps within a process are exempt.

    ✕ FailA deep hierarchy and nothing else.
    ✓ PassTwo independent routes, at least.
    2.4.6Headings and LabelsAA

    Where headings and labels exist, they have to describe the topic or purpose. This is about being informative, not merely present — 1.3.1 asks whether a heading is marked up as one; this asks whether it says anything.

    ✕ FailHeadings that describe nothing.
    ✓ PassHeadings that answer "what is under here".
    2.4.7Focus VisibleAA

    Keyboard focus has to be visible. Removing the outline because it is ugly is the single most common accessibility failure on the web, and it makes a site unusable rather than merely awkward.

    ✕ FailThe outline was removed and nothing replaced it.
    ✓ PassA ring with its own contrast and an offset.
    2.4.11Focus Not Obscured (Minimum)AA

    When something receives focus, it must not be entirely hidden behind other content. New in WCAG 2.2, and almost always caused by a sticky header swallowing whatever you just tabbed to.

    ✕ FailThe sticky header covers the field that just took focus.
    ✓ PassScroll padding reserves room for the header.
    Guideline 2.5

    Input Modalities

    2.5.1Pointer GesturesA

    Anything driven by a multi-finger or path-based gesture — pinch, two-finger rotate, swipe along a track — needs a single-pointer alternative, unless the path itself is the point. A pinch-to-zoom map still needs plus and minus buttons.

    ✕ FailZoom and rotate are gesture-only.
    ✓ PassButtons do everything the gestures do.
    2.5.2Pointer CancellationA

    Actions should fire on release, not on press — so someone who lands on the wrong control can slide off it and nothing happens. Firing on down-press removes the chance to change your mind, which matters most to people with tremors or imprecise pointing.

    ✕ FailDeleting fires the moment the pointer goes down.
    ✓ PassIt fires on release, over the control.
    2.5.3Label in NameA

    A control’s accessible name must contain the text shown on it. Voice-control users say what they see — "click Send" — and if the accessible name is something else, nothing happens.

    ✕ FailThe visible text and the accessible name disagree.
    ✓ PassThe accessible name starts with the visible text.
    2.5.4Motion ActuationA

    If moving the device does something — shake to undo, tilt to steer — there has to be a normal control that does it too, and a way to switch the motion trigger off. Someone whose phone is mounted to a wheelchair cannot shake it; someone with a tremor shakes it constantly.

    ✕ FailShake to undo, and no other way.
    ✓ PassA button too, and a setting to disable the gesture.
    2.5.7Dragging MovementsAA

    Anything you drag needs a way to do the same thing without dragging. New in WCAG 2.2. Dragging demands sustained precise pressure along a path — hard with a tremor, a head pointer, or a switch.

    ✕ FailReordering works by drag and drop only.
    ✓ PassMove up and move down, alongside the drag.
    2.5.8Target Size (Minimum)AA

    Targets need to be at least 24 by 24 CSS pixels, or spaced so that a 24px circle centred on each does not overlap its neighbours. New in WCAG 2.2. Inline links in a sentence are exempt.

    ✕ FailSixteen-pixel icons, packed edge to edge.
    ✓ PassThe same icons in 24px targets.
    Guideline 3.1

    Readable

    3.1.1Language of PageA

    Declare the page’s language in the markup. It is what tells a screen reader which voice and pronunciation rules to use, and what lets a browser offer to translate.

    ✕ FailNo language declared.
    ✓ PassOne attribute.
    3.1.2Language of PartsAA

    Passages in another language need their own lang attribute, so a screen reader switches voice for them. Proper names and words that have been absorbed into the surrounding language are exempt.

    ✕ FailA French quotation read with an English voice.
    ✓ PassThe passage declares its own language.
    Guideline 3.2

    Predictable

    3.2.1On FocusA

    Focusing something must not change the context — no navigating away, no opening a dialog, no submitting. Focus happens by accident all the time, because tabbing through a page focuses everything on the way past.

    ✕ FailTabbing onto the select navigates immediately.
    ✓ PassFocus does nothing; an explicit action navigates.
    3.2.2On InputA

    Changing a setting must not change the context either, unless you warned the reader first. Picking an option is not the same as committing to it.

    ✕ FailChoosing a country reloads the page mid-form.
    ✓ PassThe change is applied by a button, or announced in advance.
    3.2.3Consistent NavigationAA

    Navigation repeated across pages has to stay in the same relative order. You may add and remove items; you may not shuffle them.

    ✕ FailThe order changes from page to page.
    ✓ PassThe same order everywhere.
    3.2.4Consistent IdentificationAA

    The same function needs the same name and icon everywhere. Three words for one action means three things to learn, and no way to be sure they are the same thing.

    ✕ FailOne action, three names.
    ✓ PassOne action, one name.
    3.2.6Consistent HelpA

    If help is offered — a contact link, a chat widget, a help page — it has to appear in the same relative place on every page that has it. New in WCAG 2.2. People look for help when they are already stuck, which is the worst moment to have to hunt for it.

    ✕ FailHelp moves around.
    ✓ PassHelp sits in the same relative position throughout.
    Guideline 3.3

    Input Assistance

    3.3.1Error IdentificationA

    When input is rejected, say so in text, and say which field. A red outline is not an error message — it is invisible to a screen reader and to anyone who cannot distinguish the colour.

    ✕ FailA colour and a generic banner.
    ✓ PassThe error names the field, in text, and links to it.
    3.3.2Labels or InstructionsA

    Fields need labels, and any format requirement has to be stated before the reader types rather than after they get it wrong. A placeholder is not a label: it disappears the moment focus arrives, exactly when it is needed.

    ✕ FailPlaceholders standing in for labels.
    ✓ PassPersistent labels, with the rules stated up front.
    3.3.3Error SuggestionAA

    When you know what is wrong and you know how to fix it, say so. Naming the problem is Level A; suggesting the correction is this.

    ✕ FailThe error names the field and stops there.
    ✓ PassThe error says what to do instead.
    3.3.4Error Prevention (Legal, Financial, Data)AA

    For anything legally binding, financial, or destructive, give the reader a way out: make it reversible, check the input and let them correct it, or offer a confirmation step they must actively take.

    ✕ FailOne irreversible click.
    ✓ PassReview, confirm, and a window to undo.
    3.3.7Redundant EntryA

    Do not ask for the same information twice in one process. Either carry it forward or offer it for selection. New in WCAG 2.2. Re-entry is a memory and dexterity tax, and it is a pure one — the site already has the answer.

    ✕ FailThe address is typed twice.
    ✓ PassIt is offered back rather than asked for again.
    3.3.8Accessible Authentication (Minimum)AA

    Signing in must not depend on a cognitive function test — remembering a password, transcribing a code, solving a puzzle — unless there is an alternative, a mechanism to help, or the test is recognising an object or a photo you provided. New in WCAG 2.2, and this is the one that outlaws blocking paste into password fields.

    ✕ FailA puzzle, and paste disabled.
    ✓ PassPaste allowed, and a route that tests nothing.
    Guideline 4.1

    Compatible

    4.1.2Name, Role, ValueA

    Every control has to expose three things programmatically: what it is called, what kind of thing it is, and what state it is in — and it has to update as that state changes. This is the criterion that custom components fail.

    ✕ FailA custom toggle that exposes nothing.
    ✓ PassName, role, and state, all present and live.
    4.1.3Status MessagesAA

    When something important changes without moving focus — a result count, a saved confirmation, an error appearing — it has to be announced. Moving focus to it would be a change of context; this is how you tell people without interrupting them.

    ✕ FailThe basket updates silently.
    ✓ PassA live region announces it, without stealing focus.
