# Labs are self-registering folders

Each lab lives in its own folder, `src/labs/<name>/`, holding its component, its models and query module, a `lab.ts` that default-exports its registration (id, title, the criteria it is shown on, the component, `flagshipFor`) and a `lab.css` with its own styles. `src/labs/registry.ts` builds the registry from `import.meta.glob('./*/lab.ts', { eager: true })`, and each lab's e2e cases live in `e2e/labs/<name>.lab.spec.ts`, including the URL states it asks axe to scan. Parts several labs use live in `src/labs/shared/`. Adding a lab is adding a folder and a spec; no shared list is edited.

We did this because the parallel run that built the #40 labs kept colliding at merge time. Every lab ticket appended to the same five places: the `LABS` array and its imports in `registry.ts`, a section in `swatch.css` plus lines in its shared breakpoint blocks, a case in the 1,037-line `e2e/labs.spec.ts`, and rows in `STATE_PAGES` in `e2e/axe.spec.ts`. Each was an append at the end of a list, so two branches that each added a lab conflicted even though they shared nothing.

## Considered options

- **Keep the shared lists, one entry per line.** This was the convention before. It reduces conflicts but doesn't remove them: two appends at the end of the same list still collide, and the resolution is manual every time.
- **A generated registry (a script writes `registry.ts` from the folders).** Rejected. The generated file is itself a shared list that every branch rewrites, so it conflicts on merge. A glob reads the folders at build time and nothing is checked in.
- **Split multi-lab files so every lab id has its own folder.** Not done here. Seven component files hold two to four labs that share local helpers (the pointer, vision, timing, captions, media alternatives, language and text-fit labs). A folder holds one such file, and its `lab.ts` exports an array. A new lab gets its own folder.

## Consequences

- `src/labs/INDEX.md` (lab → criteria → folder) is generated by `npm run labs:index`, and a unit test fails when it is stale. It is a shared file, so it is `merge=union` in `.gitattributes`: two branches each add a row, and the test asks for a regenerate if the rows land out of order.
- A lab's `criteria` repeats the criterion records' `labs` field, which still sets the order labs appear on a page. `tests/labRegistry.test.ts` holds the two equal and also fails on a duplicate lab id, a criterion listed twice and a folder without `lab.ts`.
- Lab stylesheets load after `swatch.css` and `examples.css`, since the client entry imports those first. Six lab rules whose order against a shared rule of equal specificity decides what renders stayed in `swatch.css`. A lab rule that has to lose to a shared rule stays shared, or gets the specificity to win on its own terms.
- The lab bar's e2e tests are declared in `e2e/labs/support.ts`, so Playwright reports that file as their location. The describe name says which lab, and `--only-changed` still selects by spec file.
- `tests/retired.test.ts` follows `import.meta.glob`, so a lab folder's files count as reachable.
